# Copilot quota-exceeded (429) now triggers fallback_models on primary sessions

## What

- **Primary/host-driven sessions now fail over.** A session with no Task
  route (the user's own chat — e.g. `opencode run -m
  github-copilot/claude-sonnet-5` on an architect agent) that surfaces a
  fallback-eligible provider error now advances the session's role-scoped
  `fallback_models` chain and applies the fallback to the session's NEXT
  message (`src/index.ts` session.error branch +
  `resolveSessionChatModelOverride` at the `chat.message` boundary). Before
  this fix every fallback surface required a plugin-owned dispatch identity
  (a Task route or an SDK dispatch call site), so the README's "Automatic
  fallback to a secondary model on transient errors" promise was silently
  false for the reporter's exact configuration (issue #2989: GitHub Copilot
  enterprise `429` with plain-text body `quota exceeded` /
  `x-ratelimit-exceeded: quota_exceeded`).
- **The classifier already recognized the Copilot quota shapes** —
  `QUOTA_ERROR_PATTERN` matches both `You have exceeded your monthly quota`
  and `quota exceeded` (`provider.quota_billing` / `retry_fallback`), and the
  session.error signal extractor descends into `error.data` (#2529) — so no
  classification change was needed; this release adds the missing
  primary-session surface. Rate-limit (`retry_same`) failures advance too: a
  surfaced `session.error` means the host's own in-turn retries are already
  exhausted.
- **Sticky per session, bounded, never blocking.** The selection is scoped to
  the exact session + swarm + role, stored in the existing TTL (30 min) /
  LRU (256) bounded scoped-override state, survives invocation-boundary
  clears (a provider quota does not heal between turns), and is cleared on
  session end. An exhausted chain never throws — a primary session's user
  message is never blocked — it emits one bounded `MODEL FALLBACK:
  [primary-model-fallback-exhausted:<role>]` advisory. Each advance emits one
  `model_fallback` telemetry event (reason `quota` or `transient`) and a
  `MODEL FALLBACK: [primary-model-fallback:<role>]` chat advisory naming the
  role, the configured primary, and the fallback.
- **Recovery boundaries (deliberate, documented).** A session returns to its
  primary model via session end (or a new session), 30 minutes without a
  message on the session, or a change to the configured model chain (after
  which the stale selection reads as absent and the primary is retried).
  Switching the session's agent away from the fallback-scoped role suppresses
  the override while the other agent is active; the prior role's selection
  persists until the idle window expires, so switching back re-applies it.
  There is no in-session code escape: the pinned host's `chat.message` model
  input is type-only and cannot distinguish a user re-pick from the host
  session selection or the plugin's own prior override, so an escape trigger
  could misfire every turn.
- **Boundary that cannot be crossed:** a one-shot `opencode run` turn that
  already failed is not re-driven mid-turn — the OpenCode host owns the
  request loop. Interactive (TUI/GUI) sessions pick up the fallback on their
  next message; a failed one-shot invocation simply ends.

## Why

Issue #2989: users with a Copilot primary model and a configured
`fallback_models` entry lost the whole session to
`Error: You have exceeded your monthly quota` with no fallback attempted,
despite the documented automatic-fallback contract.

## Tests

- `tests/unit/index-primary-session-model-fallback.test.ts` (11 tests):
  advance + next-turn override with both captured Copilot shapes; single
  `model_fallback` telemetry event (`quota` reason); 401 never advances;
  rate-limit-only 429 advances; advance advisory; exhaustion (no throw, no
  override, bounded advisory); cross-session isolation; `session.deleted`
  cleanup; sticky-across-turns; non-seeding resolve.
- `tests/unit/models/model-override-state-peek.test.ts` (7 tests):

  exhausted read, and `primaryScopes:false` preserving primary scopes while
  clearing route scopes.

  checkpoint (base 58c431b506); Task-child path (C4) and classifier pins
  (C1) unchanged.
