### Fixed

- Lane-launch model failover now requires provable non-acceptance (issue #2473, completing #1615's 2026-09-05 closure contract). A thrown transport-level failure at the `session.promptAsync`/`session.prompt` launch call (ECONNRESET, ETIMEDOUT, broken pipe — no server response, host acceptance unknowable) previously matched the shared transient pattern and was re-dispatched on the fallback model against the same session, potentially issuing two accepted prompts from one logical lane launch. The launch classify callbacks now treat only a definitive server rejection (the SDK's `result.error` envelope, e.g. 429/quota/503) as failover-eligible; ambiguous transport failures and launch timeouts stay single-shot and surface the existing terminal error settlement. The thrown message text is unchanged (the #2349 byte-identical-message contract); the definitive-vs-ambiguous distinction rides on a module-private error class.
- The session.create retry cap `MAX_SESSION_CREATE_GENERATIONS` (2) is now exported so validation derives its create-attempt bound from the configured contract instead of re-hardcoding it.
- Added the frozen per-scenario launch budget manifest (issue #2473 AC6/AC7): every launch scenario row carries its effective configuration, retry owner, and explicit integer `max_host_launches` / `max_attempts` / `wall_clock_ms` bounds derived from the configured contract, with separately-accounted rows for the four retry/wake mechanisms (same-model transient retry, model fallback, collection observation, response wake). Missing, non-integer, or zero bounds fail validation, and scenario tests assert observed launch/attempt totals stay within the frozen integers. #2586 can consume this manifest directly.
