# PR-feedback rework is recoverable (scope-bound writes, one sanctioned soft reset, re-dispatchable verification)

A PR-feedback run that needs more than one edit round can now finish in-band instead of wedging on the revision digest:

- **In-scope writes survive the digest move.** Direct writes (and the coder child session's bound writes) inside a consumed PR-feedback scope's file list stay admitted after the coder's own edits change the working-tree digest. The authority is the consumed scope declaration within the head-bound workflow state, with canonical containment: existing path components resolve through the filesystem (a symlinked directory inside the scope cannot redirect a write outside it) and `..`-traversal is refused. Stage A, the ordered gates and arming keep their digest bindings (unreviewed content still cannot publish). The consumed scope itself is cleared when the intake head is rebound, so a stale scope can never authorize writes on a new ancestry.
- **The recovery is documented where the operator hits it.** The verification-ownership BLOCKED message now says to re-dispatch `swarm-pr-feedback:verification` on the edited tree (further coder writes need a fresh scope under a new task_id, and Stage A plus the ordered gates re-run), the swarm-pr-feedback skill teaches the same recovery, and the architect prompt's RESTART AFTER EDITS bullet names it.
- **One sanctioned `git reset --soft <intake head>`.** After `invalidate_pr_feedback_publication`, exactly `git reset --soft <bound intake head>` is admitted — only when the generation is invalidated, nothing is armed, HEAD is not already at the intake head, and HEAD is the single non-merge child of the intake head (audited as `pr_feedback_publication_reset_soft`). Every other reset form and condition is still refused with the existing messages.
- **Zero-coverage verification ownership is released.** A verification batch that never settled coverage — or whose artifacts bind an older digest — no longer blocks re-assignment of its items while the batch is resident in the gate state: a re-dispatch under a different lane id is accepted, and items a batch actually covers at the current digest stay exclusive. (Ownership already retired by the batch-cap GC keeps its lane binding by prior design; the recovery for those items reuses the same lane ids.)
- **The exact bound tracking fetch works while armed.** `git fetch <bound-remote> <bound-branch>` is admitted inside the armed publication window (same rule as the pre-arming window); every other fetch/checkout/merge/rebase/pull/reset still refuses.
- **A user-confirmed continuation can rebind consent to a new session.** Running the PR_REVIEW→PR_FEEDBACK continuation from a different session works when the handoff digest and finding ids match the consent record and the user confirms with the offered exact command; the rebind is written under the workflow lock and audited (`pr_feedback_consent_rebound`). Nothing rebinds silently.
- **`APPROVED` is accepted as `APPROVE`.** Feedback gate artifacts whose `[STAGE-B-REVIEW]` / `[CLOSEOUT-REVIEW]` / `[CLOSEOUT-CRITIC]` rows carry the third field `APPROVED` now pass both the lane-result validation and the structured transport recovery. `PASS` stays exact for `[STAGE-B-TEST]`, and `SKIPPED`/prose/duplicate rows are still rejected.
