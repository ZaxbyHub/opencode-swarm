# Audited PR-feedback publication invalidation and reapproval (issue #2108)

## PR_FEEDBACK publication window

The armed publication window is now a **generation-numbered state machine**
with audited invalidation and reapproval, replacing the binary armed bit whose
only drift answer was a permanent, unrecorded deadlock.

### Generation state machine

- States: `reviewing → armed → push_in_flight → published` (terminal), with
  `invalidated` (recoverable) and `cancelled_without_publication` (terminal)
  reachable from the live states.
- Every generation records the full authorization identity: canonical
  workspace identity, session/PR target, intake head, local branch + exact
  head SHA, remote name + **credential-redacted remote URL identity**, remote
  branch/tracking refs, the approved revision digest, the exact authorizing
  receipt set (Stage A + one batch per ordered phase), generation number, and
  all transition timestamps.
- `pr_workflow_status` prints a publication section (state, generation,
  attempts, invalidation reason, next step); the full audit trail is
  `.swarm/events.jsonl` (`pr_feedback_publication_*`, `pr_feedback_push_attempt_*`,
  `pr_feedback_published`).

### Audited invalidation + reapproval

- **Proven drift from ANY actor** (revision digest, HEAD, working tree,
  upstream triple, remote URL, workspace identity) durably invalidates the
  generation at the next gated interaction — under the session lock with the
  drifted component re-verified there. Unresolvable components stay armed and
  fail closed (no evidence, no transition).
- New controller tool **`invalidate_pr_feedback_publication`** is the explicit
  rework transition: it requires a reason and supersedes every
  content-dependent approval of the generation (Stage A, verification batches,
  ordered gates, scope declarations — the coder preflight then fails
  `SCOPE_NOT_DECLARED` until a fresh declaration matches the corrected
  content). Audit history is preserved; nothing is deleted.
- Evidence from generation N cannot satisfy N+1 — including the
  content-drifts-away-and-back (ABA) case. Reapproval walks the full ladder:
  verification → Stage A → four ordered gates → `complete_pr_workflow` arms
  N+1 with a fresh identity and fresh evidence join.
- New related hardening: the armed window now binds the remote's actual
  (redacted) URL and the canonical workspace identity, so a repointed remote
  or a copied `.swarm` directory cannot receive/replay the approved push.

### Durable push attempts

- Admitting the exact approved push records a durable **attempt-start**
  (intent digest, pre-push observations) under the session lock BEFORE the
  shell runs; the `tool.execute.after` recorder appends the observed result
  (fail-open). A reaper at every armed-window entry point reconciles any
  result-less attempt as `uncertain` with a fresh remote observation, so
  `push_in_flight` can never wedge — across restarts too.
- `complete_pr_workflow` requires an admitted attempt for the active
  generation and still verifies the exact remote head directly; publication is
  never inferred from an exit code.

### Cancellation without publication

- `abort_pr_workflow` with `kind: "cancel-publication"`, `cancel_publication:
  true`, and a required reason is the terminal no-publish exit from
  `{armed, push_in_flight, invalidated}`. It finalizes in-flight attempts as
  `cancelled`, discloses the observed remote head, and never grants push
  authority. Plain recovery/force aborts remain refused while armed.

### Structural exact-push parser

- The exact-push check is now a typed parser with an explicit rejection
  taxonomy (force/force-with-lease, delete, tag, wildcard, multi-refspec,
  mirror/all/prune/atomic, alternate remote/branch, credential-bearing
  remotes, config injection, `--repo=`/`--receive-pack=` overrides, shell
  wrappers, redirection, control operators, command substitution). The
  accepted grammar is byte-identical to the previous single-regex defense.

### Migration + rollback

- Pre-#2108 armed records migrate conservatively (every identity component
  must recompute and match under lock, with backing receipts present);
  otherwise they persist as generation 1 `invalidated` with a
  `legacy-migration-*` reason — never silently armed. A derived legacy mirror
  is kept while `{armed, push_in_flight}` so a rolled-back binary keeps
  enforcing the armed window, and the `.passthrough()` state schema means
  older readers ignore (never delete) the new record.
- A present-but-unreadable publication record is treated as ARMED in the
  recovery salvage (fail-closed), and the audited cancellation remains the
  exit from that state.

### Operator docs

- New `docs/pr-feedback-publication-generations.md`: state diagram, identity,
  push grammar, invalidation triggers, reapproval path, cancellation,
  migration, and inspection/export via `pr_workflow_status` +
  `.swarm/events.jsonl` — never state-file editing.
