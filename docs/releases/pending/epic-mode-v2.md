# Epic Mode v2

Epic Mode (opt-in, top-level `epic.mode.enabled`) is rebuilt around one idea: **an epic is one plan**, opened with `/swarm epic start`, run as tool-owned waves (`epic_next_wave`) of isolated, gate-admitted coders whose work is committed on an epic branch, learned from, scored, and landed back at `/swarm epic close`. With Epic disabled nothing changes (the only difference for a non-Epic setup: the architect no longer carries the Epic tools).

### Breaking changes at a glance

- `/swarm epic on` / `off` removed → `/swarm epic start` / `/swarm epic close`.
- `epic_decide_phase`, `epic_plan_waves`, `epic_record_divergence` removed → `epic_next_wave`; `/swarm epic decide` / `last` removed → `/swarm epic status`.
- Epic commits at landing (worktree merge commits on the epic branch); `update_task_status` no longer commits; git epics require worktree isolation.
- New default `epic.commit_policy: "epic-branch"`; `/swarm epic close` lands with `--land squash` (staged, uncommitted) by default.
- `epic.mode.activation_threshold` now means the intra-component density threshold.
- `epic.calibration` and `epic.mode.min_commits_for_signal` retired (accepted, ignored, warned); `/swarm epic calibration` → `/swarm epic learning` / `/swarm epic prior`.
- `/swarm turbo epic [on|off]` no longer enables anything (a redirect to `/swarm epic start`); Turbo-enabling subcommands are refused while an epic is open.
- Epic settings move to a top-level `epic` block (no `turbo` block or `turbo.strategy` needed); `turbo.epic` keeps working (migrated, warned).

## What changed

- **Breaking: Epic commits at LANDING, not at completion.** In a git epic every coder runs in an isolated worktree and its lane lands as a real merge commit (`git merge --no-ff --no-edit`) on the epic branch with the message `swarm(task <id>): <description>` and a final `Swarm-Plan: <planKey>` trailer (`planKey = sha256(planIdentityHash + '|' + planEpoch).slice(0, 16)`, unique per plan epoch). A task's work is therefore committed before `update_task_status(completed)`, and a rework coder — whose worktree is cut from HEAD — starts from the first attempt and lands without an overlap failure (before, an in-wave rework after a failed Stage B could never land). The landing is a non-interactive protocol commit (closed stdin, `--no-edit`, signing off, commit hooks skipped with `--no-verify` — they run when you commit the epic's squash at close). A landing is not attempted while the primary checkout has staged changes: the lane is preserved and `epic_next_wave` blocks `landing-index-dirty` (`EPIC_LANDING_INDEX_DIRTY`, naming the files to unstage). The former Epic "Rule 2" commit at task completion is removed: **`update_task_status` performs no git writes** under any configuration.
- **Required worktree isolation for epic coders.** A coder for a task of the open git epic is always worktree-isolated, whatever `parallelization_enabled`, `max_concurrent_tasks` or a session concurrency override say (an `auto` worktree policy acts as `required`). If isolation is unavailable the dispatch is refused with `EPIC_ISOLATION_DEGRADED` (remedy: retry, or `/swarm epic close --abandon`) — the coder never runs un-isolated in the main tree. Non-git epics keep running serially in the main tree.
- **The dispatch gate enforces the wave.** While an epic is open the delegation gate admits a coder only for a task of the active wave whose declared scope stays inside the scope frozen when the wave was issued; otherwise the dispatch is refused with a remedy: `EPIC_NO_ACTIVE_WAVE` (call `epic_next_wave`), `EPIC_TASK_NOT_IN_ACTIVE_WAVE`, `EPIC_TASK_UNKNOWN`, `EPIC_WAVE_SCOPE_DRIFT` (dispatch within the frozen files), `EPIC_BRANCH_MISMATCH`, `EPIC_STATE_UNREADABLE`. Parallelism, isolation and the slot cap come from the wave, not the execution profile: a multi-task wave dispatches all its coders concurrently (slot cap = the epic's wave width) even with `parallelization_enabled: false`, when its frozen scopes (and frozen co-change pairs) are provably disjoint — one shared verdict that `epic_next_wave` asserts at issue and the gate repeats at dispatch; a single-task wave runs serially. Scope drift is judged by containment (a frozen directory covers files beneath it), and its remedy names every real option (re-declare within the frozen scope; close or finish the task and add the extra work as a new task; abandon the epic). The wave's dispatch instructions now say scopes are frozen (no re-declaring after issue). Review findings are fixed with **fix tasks**: add them as new pending tasks of the phase with `save_plan`, and `epic_next_wave` runs them as a fix wave before the phase review is re-run — `epic_phase_review`, `phase_complete` and `epic_next_wave` say so (coders for completed tasks are refused). With Epic disabled by config a leftover sentinel never gates dispatch; with Epic enabled an unreadable lifecycle row refuses coder dispatch (`EPIC_STATE_UNREADABLE`) until repaired. PR-feedback coders are never wave-gated. (The shared `computeParallelVerdict` helper gains an optional explicit-scopes input; `plan_conflict_check` and the non-Epic gate are unchanged.)
- **Residue commits.** Main-tree files a non-coder writer (test_engineer, docs, …) wrote for an epic task are committed on the epic branch when its delegation returns (foreground or background), as `swarm(task <id>): <agent> residue` for the files that agent's own session recorded and `swarm(task <id>): residue` for the rest of the task's attributed writes and frozen scope (+ the trailer); files another still-running delegation is writing (the concurrent Stage B agent) are never swept up — only the task's attributed paths (the task's declared scope in the current wave, its write attribution, the agent's own session), literal pathspecs, `--only`, never `.swarm/`, serialized with worktree landings. A failed residue commit restores the index exactly, is a critical warning, and is retried when the wave closes. `blocked: dirty-baseline` now means uncommitted changes to **tracked** files when a new wave is about to start (the closing wave's residue is committed first); untracked files are only reported. Do not edit the working tree while a wave runs — edits inside a running task's scope can be committed as its residue.
- **Epic refs.** An epic keeps `refs/swarm/epics/<epicKey>/base` (start commit), `…/waves/<seq>` (HEAD at wave close) and `…/tasks/<id>` (the task's landing or residue commit, recorded at wave close), mirrored from the epic record (create-only `git update-ref`, idempotent). A completed dependency counts as predecessor evidence only when its task ref is an ancestor of HEAD (or it was completed before the epic started); a git failure blocks `git-failed`. `/swarm epic status --repair-refs` re-adopts a task commit a rebase or amend made unreachable (its `swarm(task <id>):` commit for this plan, else the newest commit touching its declared files; otherwise `needs-attention`). `/swarm epic close` (and `/swarm close` finalization) records every ref in the close report and deletes them, unless the new `epic.retain_refs: true`. The refs are not pushed or cloned by default (`--mirror` copies them).
- **Plan-scoped merge-failure epoch.** The shared `.swarm/worktree-merge-status.json` registry is keyed by bare task id and never cleaned. Epic ignores a failure recorded before its epoch (the wave's issue time for closing a wave, the epic's start for the auto-checkpoint skip); a failure with no timestamp stays relevant (fail closed). Completing an epic task whose merge-back failed skips the #2582 auto-checkpoint with a critical warning. `/swarm epic status` lists recorded merge failures as blocking, undated, or stale, with the remedy; `/swarm epic clear-merge-failure <taskId> [--confirm]` clears one that no longer reflects reality (without `--confirm` it only previews).

- **Breaking: an epic is now plan-scoped and opened explicitly.** `/swarm epic on` and `/swarm epic off` were removed (they now fall to the usage text). `/swarm epic start [--force]` opens one epic for the current plan; `/swarm epic close [--abandon]` closes it and writes a close report to `.swarm/epic/reports/` and `.swarm/epic-prior/reports/` (newest 50 kept, survives `/swarm close`). `/swarm epic status` shows the epic, detects an epic orphaned by a plan rename/replacement, repairs the `.swarm/epic/epic.json` sentinel, and retires Epic v1 per-session state once.
- **Start refusals.** `/swarm epic start` refuses, in order: `epic-disabled-by-config`, `no-plan` / `plan-ledger-unreadable`, `epic-already-open` (same plan — idempotent) / `epic-open-for-other-plan`, `turbo-active` (config `turbo_mode`, a session with Turbo on, or a running Lean run), `dirty-baseline` (git: uncommitted changes outside `.swarm/`), `in-flight-coders` (any coder dispatch, background delegation, unsettled settlement, or preserved/recovery lane in the project), and `not-epic-sized`.
- **Epic sizing.** A plan is epic-sized when it has at least `epic.sizing.min_tasks` (6) pending tasks, at least `min_scope_coverage` (0.8) of them carry a scope, and the Amdahl-adjusted speedup of a dry run of the Epic component planner (below) is at least `min_effective_speedup` (1.25, with `coder_fraction` 0.6). Otherwise the start is refused with the reasons and "run it in Balanced"; `--force` overrides and is recorded. Non-git projects run an epic serially (one task per wave), so they always need `--force`.
- **Epic branch (new default) and landing at close.** New `epic.commit_policy: "epic-branch" | "current-branch"` (default `epic-branch`). In a git project `/swarm epic start` checks out `swarm/epic/<epicKey>` and every Epic commit lands there; it refuses `detached-head` and `epic-branch-exists` (a leftover branch from an abandoned epic of the same plan — delete it with `git branch -D`), and rolls the start back (`branch-create-failed`) if the checkout fails. `/swarm epic close [--land squash|merge|none]` refuses a dirty tree, a missing original branch, and a detached HEAD whose commit would be orphaned before changing anything (an epic branch without changes reports `nothing-to-land`), then lands the branch onto the original branch: `squash` (default) leaves the epic's diff **staged and uncommitted** for you to review and commit, `merge` makes a `--no-ff` merge commit, `none` only switches back. The epic branch is never deleted by the plugin. A landing conflict is rolled back (`git reset --merge` for squash, `git merge --abort` for merge), the epic stays `closing`, and rerunning close resumes; landing is idempotent. `--abandon` and `/swarm close` never land — they switch back to the original branch when the tree is clean and keep (and name) the epic branch.
- **Branch drift is refused.** While an epic-branch epic is open, `epic_next_wave` blocks with `epic-branch-mismatch` (`EPIC_BRANCH_MISMATCH`, remedy `git checkout swarm/epic/<epicKey>`) when HEAD is not the epic branch, and neither a coder's landing nor a residue commit is committed onto another branch (critical warning).
- **Breaking: `epic_next_wave` replaces `epic_decide_phase`, `epic_plan_waves` and `epic_record_divergence`** (all three removed, with `/swarm epic decide` and `/swarm epic last`, the plan-wide `p` activation gate, and `.swarm/evidence/epic-promotions.jsonl`). The architect calls `epic_next_wave` (no arguments, idempotent) and does what its `status` says: `dispatch` (a wave of ready tasks with disjoint declared scopes, plus step-by-step instructions — one `Task` per task id in one message, per-task Stage A/B, then call again), `declare-scopes`, `in-progress`, `blocked` (`task-blocked`, `merge-failed`, `git-failed`, `dirty-baseline`, `predecessor-missing`, `plan-revised`, `task-reopened`, `epic-branch-mismatch` — each with its remedy), `phase-ready-for-review`, `epic-complete`, or `refused`. A wave closes once every task is completed, closed, or removed and none has a merge failure recorded since the wave was issued; phases run strictly in order — phase N+1 starts only after `phase_complete` of phase N (which now records the phase complete on the epic). Predecessors completed before the epic started need no task ref (their work was in HEAD at start); only the epic's current phase can be recorded complete by `phase_complete`. A closed or removed task's merge failure does not hold its wave, and the shared merge-status registry is trusted only while bound to this project. Global/protected-file tasks and tasks declaring a learned hot file (see learning below) run alone; with `epic.cochange.enabled`, co-changing tasks go to different waves. The epic record keeps every wave (frozen declared scopes, base and close HEAD) and per-task outcomes (rework generation, Stage A/B failure lower bounds, merge-failure snapshot, reopen count, undeclared files), shown by `/swarm epic status` and the close report. Divergence is computed at wave close from coder-session attribution (git fallback: changes since the wave's base) and feeds Epic learning. `epic_phase_review` refuses (`waves-open`) and `phase_complete` blocks (`EPIC_PHASE_WAVES_OPEN`) while a wave of the phase is open. The Epic banner is now short narration: "call `epic_next_wave` and do exactly what its status says"; per-task QA is never waived.
- **Per-component parallelism (new wave planner).** `epic_next_wave` now plans each wave over the phase's pending tasks as a conflict graph — two tasks conflict when their scopes overlap by path or, with `epic.cochange.enabled`, a co-change pair spans them: the same predicate as the wave verdict the dispatch gate repeats, so every multi-task wave it issues is provably disjoint. Global/protected-file tasks, tasks with no usable scope, and tasks declaring a learned hot file are **exclusive** and run alone, first (before, a hot-module task waited until nothing else was ready). The rest are split into connected components; a component whose density (conflicting pairs / all pairs inside it) exceeds `epic.mode.activation_threshold` is a **`serial-component`** that contributes one task per wave, while a sparser component's non-conflicting tasks share waves. A hub file therefore costs one serial cluster, not the whole phase: the other ready tasks keep filling every wave. Ready tasks are taken oldest component first (waves since it last had a task issued), so no component starves. A wave of one serial-component task has `kind: 'serial-component'`. Each wave records the phase's components (task → component, modes, densities, exclusive reasons, threshold; ≤ 256 tasks) and `/swarm epic status` shows them. The `/swarm epic start` sizing dry-run replays this planner with the same learned signals, co-change signal and threshold (before it was path-only). The internal Epic wave planner (`wave-planner.ts`) is removed.
- **Plan shaping.** With `epic.mode.enabled`, `save_plan` results gain `epic_shaping` (absent while an epic is open, and always absent with Epic off — the non-Epic `save_plan` result and work are unchanged): a plan that is not epic-sized and cannot be made so gets one line, `Plan is not epic-sized (<reason>) — run it in Balanced`; otherwise an advisory (snake_case keys) with the plan's effective speedup and up to 5 suggestions — scope advice first (`declare-scope`, `narrow-scope` for a directory entry), then by their effective-speedup gain under the sizing dry run: `extract-prerequisite` (a hub file shared by ≥ 3 tasks moved into a new prerequisite task), `isolate-hot-file`, `split-task`, `merge-tasks` — each a concrete `save_plan` patch that, applied verbatim, gives a valid plan (no dangling dependency, never a cycle) sized exactly as promised — plus `next_step` and an iteration count (`.swarm/epic/shaping.json`; from the 3rd save of the same plan it says to accept and proceed). It shapes the persisted plan after the plan lock is released, fails open, reuses the config `save_plan` already loaded, reads co-change only from the warm in-memory cache (`cochange: "cold"` ⇒ path-only, also noted in the one-liners), and is bounded by a deterministic work allowance (≈ 0.3 s added to a save at most; ≤ 200 tasks, ≤ 500 files; else `skipped-budget`). `/swarm epic start`'s `not-epic-sized` refusal shows the top 3 suggestions (from the start's own sizing); the start's sizing is itself bounded (a plan too large to size exactly is refused with a note — `--force` still opens it). The new `/swarm coupling --suggest` shows the whole advisory, read-only.
- **Breaking: `epic.mode.activation_threshold` has a new meaning** — the intra-component density threshold above (default `0.3` unchanged; lower serializes more clusters, `1` keeps tasks apart only where they conflict).
- **Breaking: Epic learning replaces the Epic v1 self-calibration.** The calibration engine (`hotModuleAdditions` — an append-only hot list — and the threshold override nothing read) is removed with `.swarm/epic/calibration.json` / `divergence.jsonl` writing. Epics now learn two things from the task outcomes each wave close records, used only by the planner (never as write authorization; the dispatch gate still checks the frozen declared scopes): **learned co-writes** — a task that declared D but also wrote f makes later tasks declaring D conflict with tasks on f (scope expansion; it only adds conflict edges, so every multi-task wave stays provably disjoint under the gate's verdict) — and a **decaying hot set** — incidents (undeclared write 1.0, merge-back failure 0.5, Stage B failure 0.25, rework 0.25 × min(generation − 1, 4), reopen 0.5 — each on the declared FILE entries, never on directory entries; a re-run task is charged only the delta over its earlier outcome) against exposures (+1 per declared file of each resolved task) with a prior mean of 0.1: a file is hot only on excess evidence (α' ≥ 1 and rate − 0.1 > `hot_excess`, where α' discounts the incidents its strongest learned co-writer explains — one declarer's undeclared write is scope expansion, not heat; writes from several declarers or other incidents still count), and a task declaring it (exact path) runs alone; an empty history plans exactly as before (neutral cold start). Two levels: the epic's **posterior** `.swarm/epic/posterior.json` (a copy of the prior at start, its digest kept in the epic record as `priorDigest`; updated once per closed wave, so an epic learns from its own earlier waves) and the **project prior** `.swarm/epic-prior/learning.json`, into which every `/swarm epic close` (any outcome, and the `/swarm close` finalization) merges the epic once — decayed × `decay_per_epic` per epic and 0.5^floor(days / `half_life_days`) by age (full weight for a whole half-life; an epic that learned nothing does not decay the prior), capped at 2000 files + 2000 co-writes. The prior survives `/swarm close`; the close output says "Project prior kept". New strict config `epic.learning.{enabled (true), decay_per_epic (0.7), half_life_days (60), hot_excess (0.25)}`. The first `/swarm epic start` imports Epic v1 `calibration.json` (hot modules ⇒ hot) and `divergence.jsonl` once into the prior (a `/swarm close` before it archives them away — nothing imported; a prior reset suppresses any later import). The epic record's `priorDigest` is shown by `/swarm epic status` and the close report; the phase-review package carries each task's attribution status. Per-task outcomes no longer carry the always-empty `mergeFailure.conflictFiles`.
- **Breaking: `/swarm epic calibration` is renamed `/swarm epic learning`** (what the planner learned and uses now; `calibration` answers with a pointer, no alias), and **`/swarm epic prior [show|reset [--confirm=<token>]]`** is new (show the project prior; `reset` previews and prints a single-use confirm token through the shared two-step destructive-confirm primitive, `reset --confirm=<token>` clears it).
- **`epic.calibration` is retired** — the whole block (`enabled`, `floor_threshold`, `tighten_step`, `loosen_step`, `loosen_window`) is accepted and ignored with a "retired" loader warning naming `epic.learning`, a `retired-config-key` doctor finding, and a `deprecated` JSON-schema entry. `calibration.enabled: false` does not disable learning (set `epic.learning.enabled: false`).
- **`epic.mode.min_commits_for_signal` is retired.** It is accepted and ignored: stripped before validation and read by nothing, with a precise "retired" warning from the loader (once, `/swarm diagnose`) and a `retired-config-key` finding from `/swarm config doctor` — instead of being reported as an unrecognized key with a `stripped_keys` config recovery. `opencode-swarm.schema.json` keeps it marked `deprecated`, so editors do not reject it.
- **One project probe drives every Epic behaviour.** The wave dispatch gate, the landing seam, residue commits, the auto-checkpoint guard, the `epic_phase_readiness` gate, the Epic banner, `epic_next_wave` / `epic_phase_review`, and per-task attribution retention all ask "is an epic open for the current plan?". The check is sentinel-first: a project with no open epic pays one `existsSync` — no database open, no config read, no write. The per-session Epic rows, their 24 h TTL and heartbeat, and the session-lifecycle hooks are gone; `/swarm reset-session` no longer touches Epic (an epic outlives a session); `/swarm close` closes an open epic as `abandoned-by-swarm-close` before archiving. While an epic is open the standard parallel-dispatch advisory is suppressed (the Epic banner and `epic_next_wave` own dispatch guidance), and each wave is capped at the epic's width.

- **Stage A is credited to the right task in a parallel wave.** `pre_check_batch` results were credited to the session's last-returned coder, so in a multi-task wave the checked task never reached Stage B (found in a live 4-coder wave). While an epic is open, a gate run is credited by its `files` to the wave task whose frozen scope owns them, or to none with an advisory.
- **Configurable phase-review timeout.** New `epic.phase_review.timeout_ms` (10 s – 30 min, default 300 s, matching `auto_review.timeout_ms`) bounds each `epic_phase_review` role. On slow models the reviewer or critic could run past the fixed 5 minutes, which records a fail-closed REJECTED and forces a re-run.
- **Epic needs an OpenCode 1.x host for now.** Epic's worktree-isolated coders and its phase review are dispatched through the OpenCode SDK client, which the OpenCode 2 adapter does not provide yet (docs/host/v2-hook-inventory.md). `/swarm epic start` now refuses on such a host with `host-unsupported` instead of opening an epic whose coders would all be refused. The check is capability-based, so Epic works on OpenCode 2 once the adapter supplies a client.
- **Epic phase review works on OpenCode Zen's free tier.** The free tier refuses (HTTP 403) a request that disables `bash`, which every plugin review dispatch does, so on free models the phase reviewer came back empty and the epic could never pass its first phase review. `epic_phase_review` now retries an empty response once with only `bash` re-enabled (within the same per-role timeout, with an instruction not to change anything; every other tool stays denied — still narrower than the standard per-task reviewer and critic, which deny only write/edit/patch among the built-ins) and records the `tool_profile` it used. Because the dispatcher reports any provider-side error as an empty response, the retry fires on every empty completion, not only the free-tier refusal; a second empty response stays a fail-closed REJECTED. The shared dispatcher gains an optional `tools` map for this; every other caller still sends the full read-only map.
- **Epic scorecard and `/swarm epic report`.** Every epic now has a scorecard computed from its record: tasks completed in the epic (and adopted at start), waves (count, parallel, mean/max width), time over closed waves — wave span, task issue→resolve time, and their ratio labelled a **concurrency factor, not a speedup** (it includes queueing behind serialized QA) plus idle time between waves — conflicts (merge-back failures, undeclared writes), rework (extra generations, reopens), first-pass gate rates for Stage A, Stage B and the phase review (upper bounds: the failure history is bounded), forced/sizing at start, the inherited prior and the learned hot files. The close report (`epic-report-v2`) embeds the full scorecard. New **`/swarm epic report [<key>|last] [--format json]`**: the live scorecard of the open epic, or a past epic's from `.swarm/epic-prior/reports/` (`last` = newest; a report or epic key). `/swarm epic close` prints a one-line scorecard summary.
- **Planner regression harness.** `scripts/lib/epic-sim.ts` (outside the plugin bundle) replays fixture plans through the real Balanced, Lean lane and Epic component planners (with learning across epochs) under a seeded, simulated cost model and guards makespan, conflicts and rework against a golden file; it runs as a normal unit test, and `bun scripts/epic-bench.ts` prints the table. It is a planner regression harness — it makes **no claim about real speed**.
- **Epic config is a top-level `epic` block.** Epic Mode is its own mode, not a Turbo overlay: its settings (`mode`, `cochange`, `learning`, `sizing`, `commit_policy`, `retain_refs`, same keys, defaults and strict validation as before) now live under top-level `epic` — `{ "epic": { "mode": { "enabled": true } } }` — and need no `turbo` block. The old `turbo.epic` path is still accepted, with no removal planned. The loader moves it to `epic` before validation, so it no longer needs `turbo.strategy`, and a `turbo` block that held only `epic` is dropped. The move happens in each config file before the user and project files are merged. Within a file, top-level `epic` wins for each key it sets and the legacy block fills in the rest. Across files the usual precedence applies (project over user). The loader logs one warning (`turbo.epic is deprecated — move it to top-level epic`) and labels keys it recovers from the legacy block `(from turbo.epic)`. `/swarm config doctor` reports `legacy-epic-config-path` without an automatic fix and reports problems inside a legacy block at its `turbo.epic.*` path. `opencode-swarm.schema.json` marks `turbo.epic` as `deprecated`, but editors still expect `turbo.strategy` there; moving the block clears that. Retired keys are accepted and reported under either path. `epic` is declared in the config-consumption ratchet (#2904). Every Epic reader resolves the block through one function, `resolveEpicConfig` in `src/epic/config.ts`.
- **For contributors: Epic source moved to `src/epic/`** (from `src/turbo/epic/`; tests from `tests/unit/turbo/epic/` to `tests/unit/epic/`). Apart from deleting the unused Epic v1 barrel `src/turbo/epic/index.ts` (import Epic modules directly), only file paths and import paths changed. Epic still imports Lean Turbo's conflict predicates from `src/turbo/lean/` and never modifies them. The coordination-store namespaces `turbo.epic.lifecycle` / `turbo.epic.session` keep their names because they are persisted data. A maintainer guide, `src/epic/README.md`, covers the module map, the invariants, every Epic seam in shared files, the persistence map, the test map and recipes. It is linked from `AGENTS.md`, `README.md` and `docs/modes.md`.
- **Bundle size cap.** `dist/index.js` grows by about 223 KB with Epic v2's own code (upstream 9,911,593 B → 10,134,609 B at the time of writing); the packaging smoke cap `MAIN_BUNDLE_MAX_BYTES` is raised from 9.5 MiB to 10.5 MiB (#1583 precedent; #1582 identifier minification remains the structural fix). The planner regression harness lives under `scripts/` and is not bundled.

## Why

Committing an epic task at completion deadlocked in-wave rework: the first attempt landed unstaged, the rework worktree (cut from HEAD) lacked it, and the rework's landing overlapped those uncommitted bytes forever; tests the test_engineer wrote stayed uncommitted and paused the next wave. Task ids also repeat across plans (every plan has a `1.1`), so history-grepped markers from an earlier plan could satisfy the current plan's dependencies; epic refs and plan-scoped messages bind every piece of evidence to this epic.

## Migration steps

- Architect prompts or automation that call `epic_decide_phase`, `epic_plan_waves` or `epic_record_divergence` must call `epic_next_wave` instead. `/swarm epic decide` / `/swarm epic last` are gone; use `/swarm epic status`.
- Replace `/swarm epic on` with `/swarm epic start` (once per plan) and `/swarm epic off` with `/swarm epic close` (or `/swarm epic close --abandon` with tasks still pending). Legacy Epic v1 per-session state is retired the first time `/swarm epic status` runs; nothing is opened automatically.

- Epic tasks no longer get a commit from `update_task_status`. Close an epic opened before this release (`/swarm epic close`, or `--abandon`) and start a new one; its coders then land as commits.
- To make a hand-made commit count for a task, give it the subject `swarm(task <id>): …` and a final `Swarm-Plan: <planKey>` line (the plan key is shown by `/swarm epic status`), then run `/swarm epic status --repair-refs`.
- Mirroring a repository with `--mirror` also copies `refs/swarm/*`; ordinary push/clone does not.
- Remove `epic.calibration` from your config (ignored with a warning); to turn learning off set `epic.learning.enabled: false`. Replace `/swarm epic calibration` with `/swarm epic learning` / `/swarm epic prior`. Existing Epic v1 calibration and divergence files are imported into the project prior on the next `/swarm epic start`.
- Remove `epic.mode.min_commits_for_signal` from your config (it is ignored with a warning). Revisit `epic.mode.activation_threshold` if you set it: it now decides which conflict clusters run one task per wave.
- `/swarm turbo epic on` users: open epics with `/swarm epic start` (Turbo stays off while an epic is open).
- Move your `turbo.epic` block to top-level `epic` (same keys). Nothing breaks if you don't: the legacy path keeps working, with one deprecation warning per session and a `legacy-epic-config-path` doctor finding. You can drop a `turbo` block that existed only to carry `epic`.

## Known caveats

- The scorecard's concurrency factor and the planner regression harness are not speed measurements; sizing's effective speedup is a dry-run estimate.

- Learned signals are path-based heuristics: a co-write learned on one plan serializes tasks of a later plan that declare the same files, and a single observation keeps expanding scopes until a later epic that learned something closes (`decay_per_epic`) or a half-life (60 days) passes. Inspect with `/swarm epic learning`; clear with `/swarm epic prior reset`.

- Epic keeps Turbo off where it can see it: `/swarm epic start` refuses on config `turbo_mode`, a Turbo session in the same process, or a running Lean run; while an epic is open, config no longer seeds Turbo into new sessions, restored sessions come back with Turbo off, and `/swarm turbo` refuses to enable it. Turbo enabled in a different OpenCode process on the same project is not detectable.

- A residue commit attributes a non-coder writer's files by declared scope and session write attribution; a manual edit to a tracked file no task declared still blocks the next wave (`dirty-baseline`) until you commit or discard it. Declare each task's test files in its scope.
- Landing merges and residue commits skip repository commit hooks (`--no-verify`) and signing; they run when you commit the epic's squash at close.
- A plain `git rebase` of the epic branch drops the landing merge commits unless `--rebase-merges`; after any rewrite run `/swarm epic status --repair-refs`.
- A lane recovered later via `/swarm lanes` lands through the recovery path's own committed merge with its default message; its task commit is recorded as the wave's close HEAD.
- Renaming or replacing the plan while an epic is open orphans the epic: Epic behaviour turns off for the new plan, `/swarm epic status` says why, and `/swarm epic close --abandon` closes it.
- With the default `epic-branch` policy, keep the epic branch checked out until the epic closes; switching branches mid-epic stops Epic planning, and landings / residue are not committed until you switch back. Set `epic.commit_policy: "current-branch"` to keep the previous behaviour (commits on the branch current at start, nothing landed at close).
- `--land squash` stages the epic's changes without committing them; the `swarm/epic/<epicKey>` branch stays until you delete it, and starting a new epic for the same plan is refused while it exists.

- Plan-ledger re-roots: a `save_plan` that renames the plan's title or swarm, `/swarm rollback`, or a truncated-ledger recovery mints a new plan root, which orphans the open epic (see above).
