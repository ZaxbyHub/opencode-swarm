# Typed terminal failure class for abandoned lanes (issue #2615)

## What

- `BackgroundDelegationWorkflowLaneFailureClass` gains a `'liveness'` member (replacing the long-dead `'deadline'`, removed with its last producer in #2381): a terminal whose cause is host-side abandonment of the lane — presumed-stale sweeps, an unobservable host session, or an operator `cancel_pending` — now carries a typed failure class instead of a classless terminal.
- Producers of `'liveness'`: the `collect_lane_results` `cancel_pending` settle; the Task-side presumed-stale sweep (`sweepStaleDelegations`, whose `stale` flip now carries a bounded reason + digest + class); and the collect-path stale sweep's new unobservable-host branch — a lane past the stale horizon whose host session readiness is `unknown` (absent session or no status client) and which has no transcript result previously stayed pending forever; it now settles through the shared exactly-once terminal claim with a bounded reason naming the lane and `host session unobservable`. An `idle` host session past the horizon still flips to `stale` exactly as before — now carrying the same typed `'liveness'` result, merged over any pre-existing partial result exactly as the Task-side sweep does.
- Launch rejections are typed for every lane, not only PR-review lanes: `appendAsyncLaneLaunchError` now stamps `workflowLaneFailureClass: 'resource'` unconditionally (the lane never started, so no child evidence can exist).
- The PR-review circuit classifies a `'liveness'` terminal explicitly as `{kind: 'ignored', reason: 'host_abandonment'}` before its generic status switch: host abandonment is never a repeated typed dispatch failure and never opens the provider circuit.
- The partial-base-coverage disclosure vocabulary (`src/pr-review/completion.ts`) admits `'liveness'`: the disclosure schema enum, the safe-details map, and the structured-receipt mapper now carry the disclosure-side vocabulary `BackgroundDelegationWorkflowLaneFailureClass | 'deadline'` — `'deadline'` stays legible for durable pre-#2615 disclosures and structured `DEADLINE_EXCEEDED` receipts, while a cancelled/stale/swept lane's `'liveness'` class settles a dimension through `write_pr_review_artifact(partial_base_coverage)` / `complete_pr_workflow(INCOMPLETE)` instead of the unadmittable classless terminal. Admission reaches the class on two routes: claim-settled lanes (operator cancel, unobservable host) through their claimed `terminalResult`, and claim-less stale flips through a `record.result` fallback in `latestTypedFailureForBaseDimension` — a record already holding a terminal failure status (`stale`/`cancelled`/`error`) without a claim event contributes its class-carrying `record.result`, mirroring the circuit's existing `terminalResult ?? result` trust rule.
- Both `collect_lane_results` descriptions (the tool definition and `TOOL_METADATA`) no longer claim a "pure OBSERVER": they state that a presumed-stale sweep runs on every call — idle host sessions settle to `stale`, unobservable host sessions to a typed `liveness` error — and that `cancel_pending` cancels remaining pending lanes. Both texts stayed at or under their previous length (architect prompt budget).

## Why

The #2614 incident left 12 lanes pending for 41–52 minutes until an operator cancelled, and `complete_pr_workflow(INCOMPLETE)` was refused because no lane carried a typed terminal failure. Three terminal paths still produced classless terminals: operator cancellation, the Task-side presumed-stale flip, and lanes whose host session was unobservable (retained forever as open rows). With a typed `'liveness'` class on each, the partial-base-coverage admission gate can settle an abandoned PR-review dimension without `abort_pr_workflow`, and the circuit can distinguish "the host walked away" from "the provider keeps killing typed dispatches" — the latter opens a circuit, the former never does.

## Notes

- The vocabulary is closed against declared-but-unproduced members: new suite `tests/unit/pr-review/lane-failure-class-parity.test.ts` mirrors the union with a `satisfies Record<...>` key set (adding a member breaks compilation) and asserts a grep-able `workflowLaneFailureClass: '<member>'` producer exists in `src/tools/dispatch-lanes.ts` / `src/background/pending-delegations.ts`; it also covers the cancel settle, the Task-side stale-flip result (fresh and merged over a pre-existing partial), the collect-path idle-flip and unobservable-host settles, the busy-batch wedge shape, and the circuit classification (8 tests).
- Acceptance (c) is pinned by `tests/unit/tools/write-pr-review-artifact-liveness-admission.test.ts` in two fixtures that each admit an INCOMPLETE disclosure carrying `failure_class: 'liveness'` (tool result, on-disk disclosure, and bounded safe detail): a five-covered + one-cancelled-liveness lane (settled through the terminal claim) and a five-covered + one-stale-swept lane (driven through the real Task-side `sweepStaleDelegations`, admitted through the `record.result` fallback) — the pre-fix tree fails both admissions with the `lacks a typed terminal failure` refusal.
- Exactly-once is preserved on every settle path. The cancel and unobservable-host settles route through `settleDelegationTerminal` (the shared terminal claim), and the collect-path sweep re-reads the record after the readiness call before settling so the CURRENT record state is claimed. The Task-side sweep instead settles by a direct status write under the already-held store lock — the claim path is not used there — so exactly-once rests on the sweep's status guard (only open `pending`/`running`/`ingestion_error` records past the horizon are flipped) and the `#2482`/`#2244` eventless-terminal end emission.
