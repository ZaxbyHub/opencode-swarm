# Gates configuration is now actually wired

## The `gates.*` configuration section is now actually wired (and the docs no longer promise keys that never existed)

Every documented quality-gate switch was dead: setting `gates.syntax_check.enabled: false` (or any of the other five sections) parsed cleanly and then influenced nothing, because no production path ever delivered the loaded config to the gate tools. Seven documented options (`placeholder_scan.patterns`, `placeholder_scan.block_on_empty_functions`, `sast_scan.severity_threshold`, `sast_scan.use_semgrep_if_available`, `sbom_generate.output_format`, `sbom_generate.include_dev_dependencies`, `build_check.commands`) never existed in the schema at all and were silently stripped from your config.

**What works now:**

- `gates.<section>.enabled: false` disables its gate through the real tool path — all six sections (`syntax_check`, `placeholder_scan`, `sast_scan`, `sbom_generate`, `build_check`, `quality_budget`). Disabled gates return a non-blocking skip/pass with an explicit "disabled by configuration" marker and write no evidence.
- `placeholder_scan` now honors user-written config keys: `deny_patterns` (replaces the built-in pattern set), `allow_globs`, `sentinel_allowlist`, and `max_allowed_findings` (tolerate up to N findings before failing; default 0 keeps the old any-finding-fails behavior).
- `quality_budget` thresholds from the config file apply, and a file-level `enabled: false` is an absolute kill switch — a per-call `config: { enabled: true }` from an agent cannot re-enable it.
- `pre_check_batch` honors `gates.sast_scan.enabled: false` (skipped via the same `sast_skipped: true` shape the QA profile uses) and `gates.quality_budget`.
- Config values only apply when you actually wrote the key: schema defaults no longer masquerade as custom user intent (a config containing only `placeholder_scan: { enabled: true }` keeps the full built-in comment/string/code scanning).

**Related fixes shipped together:**

- `placeholder_scan.sentinel_allowlist` — a real schema key — was previously stripped as "unknown" by a hand-maintained key registry that had drifted from the schema. The registry is now derived from the schema itself, so this class of false-strip cannot recur.
- Discarded `gates.*` keys were already surfaced by `/swarm diagnose` (deferred warnings) and `/swarm config doctor`; a regression test now pins that, and repeated tool invocations no longer flood the warning buffer with duplicates.
- A new `gates-docs` drift-check detector guards the docs↔schema↔reader triangle: a documented key with no schema entry, a schema key with no documentation, a registry drift, or a schema section with no registered reader each fail the drift check (blocking under `DRIFT_CHECK_ENFORCE=1`).

**Documentation:** `docs/installation.md`'s Quality Gates section now documents exactly the keys that exist, with migration notes for each removed ghost key (e.g. use `deny_patterns` where the docs used to claim `patterns`).
