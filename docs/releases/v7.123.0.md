# Canonicalize issue-tracer with a full-resolution contract and per-agent adapters

## What changed

- Rebuilt `issue-tracer` as ONE canonical, agent-neutral skill at
  `.opencode/skills/issue-tracer/` (SKILL.md + references/ + assets/ + scripts/),
  replacing the previous per-agent whole-text forks in `.claude` and `.agents`.
- Reclassified the skill in `src/config/skill-mirrors.ts` from `agents-only` to
  `adapter`: `.claude/skills/issue-tracer/SKILL.md` and
  `.agents/skills/issue-tracer/SKILL.md` are now thin shims that reference
  `../../../.opencode/skills/issue-tracer/SKILL.md` (the swarm-pr-review adapter
  shape). `.agents/skills/issue-tracer/agents/openai.yaml` is retained as the
  per-agent manifest, matching the swarm-pr-review adapter.
- Bundled the canonical skill to npm consumers: added `issue-tracer` to
  `BUNDLED_PROJECT_SKILLS` (`src/config/bundled-skills.ts`),
  `package.json#files`, and `REQUIRED_PROJECT_SKILL_SLUGS`
  (`scripts/package-smoke.mjs`).
- Installed a mandatory **Full-Resolution Contract** (complete fix, no deferred
  work, no unwired code, edge-case coverage, defect-class eradication,
  acceptance-criteria closure, evidence-over-assertion with review-SHA binding)
  and a new **Phase 4.2 Recurrence Sweep and Guardrail** phase.
- Added gate-integrity upgrades to the critic gate: reviewed-SHA/diff-hash
  recording in every verdict, strict reviewer inputs (diff + artifacts, not the
  implementer's plan/critic narrative), a three-cycle loop bound with user
  escalation, a heading-level deferred/scoped-out/unwired check in both critic
  paths, and a stricter root-cause confidence rule.
- Added `references/untrusted-content.md`, `references/install.md` (per-agent
  discovery + user-level shadowing + `metadata.version` reconciliation),
  `references/method-provenance.md`, and two gate scripts under
  `.opencode/skills/issue-tracer/scripts/` (`scan-deferred.sh`, `trace-init.sh`).
- Unified the trace root to `.agents/issue-traces/<issue-slug>/` across all
  copies (replacing `.claude/issue-traces/`, `.codex/issue-traces/`,
  `.Codex/issue-traces/`, `.zcode/`); the skill excludes it via
  `.git/info/exclude` at runtime, and `.gitignore` now also lists it for repo
  hygiene. Added a root `AGENTS.md` reading-order row for issue work.

## Why

The skill was distributed as per-agent whole-text forks that drifted silently
(the Codex copy even declared itself "the Codex-native version"). Canonicalizing
to the repo's proven adapter pattern gives all five agent surfaces (OpenCode,
Claude Code, OpenAI Codex, ZCode, GitHub coding agents) a single source of truth,
and installs a blocking full-resolution contract so partial fixes, deferred work,
and unwired code are structurally forbidden rather than left to vigilance.

## Migration steps

No migration required for consumers. Contributors who kept a user-level
`issue-tracer` copy (e.g. `~/.claude/skills/issue-tracer/`) should reconcile it
against `metadata.version` in the canonical `SKILL.md` per
`references/install.md`, since a stale user-level copy can shadow the project
canonical.

## Breaking changes

None. The skill name, trigger surface, and phase workflow are preserved and
expanded.

## Known caveats

- The canonical frontmatter retains `audience: swarm-plugin` (required by the
  repo's `detectSkillAudienceDrift` drift check) in addition to the Agent Skills
  spec fields (`name`, `description`, `license`, `metadata.version`,
  `metadata.source`); it is not removed, because removing it would fail
  `bun run drift:check`.
- The Agent Adapter table maps each surface to its concrete tools. ZCode is
  mapped to the Codex-native tool surface (`apply_patch`/`update_plan`/`web`) as
  a Codex-family CLI that shares the `.agents/skills/` discovery tree; verify
  against your ZCode build if its tool names differ.
