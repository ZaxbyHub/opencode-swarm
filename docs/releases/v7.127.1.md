# PR-workflow response gate: banner prefix instead of text replacement

## What

The `experimental.text.complete` hook (`src/hooks/pr-workflow-response-gate.ts`)
previously **replaced** every architect text part with a "FINAL RESPONSE
BLOCKED" notice while a durable PR-workflow gate was active. This erased all
intermediate reasoning, making `/swarm pr-review` and `/swarm pr-feedback`
nearly unusable: every thought, status update, and planning note was
overwritten with the block message, and the auto-wake loop amplified the
effect by re-prompting on every idle boundary.

The hook now **prepends** a compact workflow-active banner and preserves the
model's original text below it:

```
--- [PR_REVIEW WORKFLOW ACTIVE — output below is not a terminal verdict;
     only `complete_pr_workflow` clears the gate; if the bind/checkout path
     is unreachable call `abort_pr_workflow` or run `/swarm abort-pr-workflow`] ---

Let me fetch the PR head and verify the merge base...
```

The model's reasoning is visible to the user, but the banner makes clear the
output is not a terminal verdict. Recovery notices for suspended/interrupted
states remain always-visible in the banner. Security is unchanged:
`complete_pr_workflow` is the publication clearing path, while
`abort_pr_workflow` can clear an unarmed workflow after its safety checks
pass; the banner is a visible signal, not a security boundary.

## Why

The text gate was a redundant secondary defense — the real gate is
tool-gated (`completePrWorkflow`/`abortPrWorkflow`), not text-gated.
Unconditional replacement destroyed the model's ability to communicate
progress, causing the "constant firing" symptom reported by users.

## Migration

No breaking changes:
- The gate state lifecycle, tool interception, and auto-wake loop logic are
  unchanged.
- The auto-wake continuation prompt (`blockedText`, used only in the
  `session.idle` → `promptAsync` path) was updated to say "The workflow
  gate is still active. Continue with…" instead of the false claim "The
  replaced text is not a valid review."
- Existing tests were updated to assert the banner + preserved-text
  coexistence rather than text replacement.

# PR_REVIEW/PR_FEEDBACK mechanical-gate deadlock: bounded resume + abort escape hatch

## What

Closes an unrecoverable deadlock in the PR-workflow mechanical gates
(introduced in `feat(pr-workflow): enforce mechanical review gates`). When
`/swarm pr-review` activated a `PR_REVIEW` gate, the architect could become
trapped in an unbounded auto-resume loop with no tool path to clear the gate
— for example when a compound `git fetch … && git checkout …` was repeatedly
rejected as read-only shell syntax and the working tree never reached the PR
head. Every turn ended with the gate replacing the architect's text and
`session.idle` mechanically re-awoke the session indefinitely.

Two compounding faults are fixed:

1. **No escape hatch.** `clearPrWorkflowGateState` was only reachable from
   `completePrWorkflow` on terminal success. Once the gate activated without
   a binding (the normal `/swarm pr-review` path) and the architect could
   not reach completion, the gate was permanent for the session. This adds:
   - an `abortPrWorkflow` hook (`src/hooks/pr-workflow-gate.ts`) that clears
     the durable gate, fail-closed on armed publication and on in-flight
     lanes, and appends a non-fatal audit event to `.swarm/events.jsonl`;
   - an `abort_pr_workflow` tool (architect-callable, registered through the
     full tool-metadata/manifest/index/controller chain);
   - a `/swarm abort-pr-workflow` restricted command (human-only escape
     hatch for when the wake budget has suspended).

2. **Unbounded auto-resume.** `pr-workflow-response-gate.ts` woke the gated
   session on every `session.idle` with only a concurrency guard. This
   replaces it with a progress-aware wake budget: the consecutive-unproductive
   counter resets whenever the durable gate's `revision` advances (so healthy
   long reviews never exhaust it) and suspends further auto-resumes after a
   small number of consecutive unproductive wakes. `textComplete` prepends a
   workflow-active banner to the architect's text (preserving the model's
   reasoning below it) so the user-visible surface always names the recovery
   path.

The banner text now names `abort_pr_workflow` and `/swarm abort-pr-workflow`
and the triggering conditions, so a trapped model (and the user) see the exit
on every turn. When the budget suspends, the banner carries an operational
notice naming the recovery command.

Authorization and defense-in-depth:
- `abortPrWorkflow` operates on the raw caller `sessionID` only — lane/child
  sessions cannot abort the controller's gate.
- It refuses while `prFeedbackReadyToPublish` is armed at BOTH the hook and
  the tool gate (clearing an armed gate would drop the immutable-commit
  binding and leave a half-published commit).
- It refuses while `swarm-pr-*` delegations are in flight (matches
  `completePrWorkflow`).

## Why

AGENTS.md §9 (guardrails/retry) and §10 (chat/system hooks) require bounded,
recoverable behavior. A gate that activates on a slash command, cannot be
aborted, and auto-resumes forever violates "recoverable" and "bounded"
directly. The incident report shows the architect looping for dozens of turns
with no recovery path. The fix keeps the structured-review coverage guarantees
intact while guaranteeing the gate can always be cleared.

## Migration

No breaking changes:
- The new `abort_pr_workflow` tool and `/swarm abort-pr-workflow` command are
  additive. Existing PR_REVIEW/PR_FEEDBACK workflows are unaffected — the
  happy path (reach `completePrWorkflow`) is unchanged.
- The wake budget (`MAX_CONSECUTIVE_UNPRODUCTIVE_WAKES = 5`,
  `WAKE_COOLDOWN_MS = 30_000`) only affects sessions that fail to advance
  the durable gate's `revision` across idle cycles. A review that is actively
  dispatching lanes, recording trigger evaluations, binding the merge base,
  or otherwise mutating the durable gate state bumps `revision` on every
  successful state-mutating controller call and never hits the budget.
  Read-only operations (`collect_lane_results` polling, grep, read) do not
  bump `revision` by design; an architect that only polls for a long stretch
  without advancing the durable gate is treated conservatively.
- Audit events are appended to the existing `.swarm/events.jsonl` (no new
  ledger file).

## Caveats

- The wake-budget constants are judgment calls surfaced here for future
  tuning. A healthy review that makes progress is unaffected; only a
  genuinely stuck session reaches the budget.
- The compound-shell rejection in `isAllowedPrWorkflowReadOnlyShell` is left
  unchanged (it is the correct read-only-intake posture). The architect prompt
  and skill updates now explicitly instruct running `git fetch` and
  `git checkout` as two separate standalone commands when the compound form
  is rejected.
- Abort is a recovery tool, not a coverage shortcut. The architect prompt and
  both swarm-pr-review/swarm-pr-feedback skills instruct using it only when
  the bind/checkout path is genuinely unreachable.
