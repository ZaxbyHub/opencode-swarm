# Redaction fill tolerance for the memory scanner, capability/executor TTL recovery, and the vendored-surface type-probe gate

Closes #3743, closes #3756 (collated; the #3743 investigation note suggested two PRs — the collation follows the standing maintainer authorization for multi-issue PRs while the diff stays sectioned per subsystem).

## What changed

- **Memory secret scanner (findSecrets / containsSecret / redactSecrets)** now matches a Cf/DI-deleted condensed view in addition to the raw text (the #3730 two-view pattern, mirrored inline per that precedent): a credential split by an invisible byte (U+200B etc.) is detected and redacted exactly like its plain form, across all 14 pattern families. Per-pattern sequential-priority semantics are preserved (base outputs byte-identical for non-Cf inputs). The condensed view is skipped entirely when the text has no zero-width byte, is built once per call for the read-only `findSecrets`/`containsSecret` paths, and redaction rebuilds its output in a single pass — so the two-view change adds no measurable cost on normal input (a dense 1.4 MB / 50k-secret blob redacts in ~60 ms, and a 1 MB secret-free blob in ~8 ms; the pre-existing per-record `containsSecret` cost drops ~30×). Because durable-secret rejection decisions change, `REDACTION_POLICY_SALT` and `FINGERPRINT_ALGORITHM_VERSION` bump 3 → 4: existing cohort members surface as "re-run `/swarm memory link`" instead of a false config mismatch (the same remedy as the #1466/#3382 bumps).
- **JWS scanner residuals** (`src/utils/jws-redaction.ts`): a dir-JWE whose IV fails the tokenLike predicate no longer stays fully visible (the IV position is structural); a 13–39-char standard header that strictly decodes to a JSON object is redacted (the 40-char floor stays for non-JSON headers, so benign dotted paths stay visible); glued-composition tails are recovered via candidate enumeration + a header-overreach clamp + a coverage-preserving final normalization. One approved widening: two clamp-adjacent spans may merge across an internal separator dot (coverage never shrinks; same disclosed over-redaction class as the existing `…sig.Snapshot` absorption).
- **Sandbox capability memo TTL**: a degraded win32 PowerShell-fallback capability memo expires after 60 s (env-overridable test knob) instead of pinning for the process lifetime — after a transient runner-probe failure + recovery, policy assessment and `/swarm diagnose` re-derive within a bounded interval, and the executor-mechanism-drift hard block no longer wedges every shell call. A `none`-strength executor is TTL-bounded in `getExecutor` like null/weak (construction-time class; an explicit `disable()` stays permanent by design). `/swarm diagnose` never reports a `none` executor as strong.
- **Shell-audit dash-flag redaction** was rewritten as a manual linear scan (instead of the `{0,64}`-bounded regex arms) so a sensitive keyword anywhere in a flag name — including a long name, or a flag embedded inside another flag's value (`--cfg=prefix--api-key=SECRET`) — is still redacted, closing a gap where the earlier `{0,64}` bound let flag names longer than 64 chars escape. The scan is O(n) (a keyword pre-check short-circuits commands with no sensitive keyword), so a 20,000-dash `git commit -m` audit runs in a few ms (down from ~5–7 s).
- **Vendored-surface type probe is wired into CI**: the ci.yml quality job runs `scripts/check-vendored-surface-probe.ts` (behind the release guard), which compiles `tests/unit/host/v2/vendored-surface-2-3-0.type-probe.ts` with the pinned local TypeScript — including a `--self-test` that breaks `types.ts` and requires the gate to catch it. New C3 source-scan rows reject a `| undefined` widening of `V2JsonValue` and pin `prompt: string` on `V2ExperimentalGenerateApi`. The gate is invoked directly (no package.json alias): package.json is release-please-owned.

## Why

- #3743: two probe-verified siblings of the #3730/#3736 defect family (memory-scanner zw-split gap; capability-probe memoization staying weak after executor recovery) plus the five absorbed redaction-scanner residuals from PR #3742's review rounds.
- #3756: the vendored-surface type probe was executed by no automated gate (verified by three independent reviewers during PR #3741) — its assignability contract rotted silently on every pin refresh.

## Notes for reviewers

- The redaction-policy/fingerprint version bump means cohort configs written before this change re-link on next `/swarm memory link` (legacy v1 classification unchanged).
- The `as never` hook-call cast removal (AC11 of #3756) deliberately rides the #3642 epic, not this change.

# Test-infra reliability: cross-file co-run pollution fix + acceptance-validator hardening

## What

Fixes the cross-file test-process pollution that made `guardrails-swarm-path-guard.test.ts` and
`guardrails.test.ts` fail 17-58 ALLOWED legs only when co-run with `guardrails-modified-files.test.ts`
(issue #3608), and the three stale-acceptance-validator quirks tracked in #3381.

- `src/hooks/guardrails/execution-stall.ts`: the module-level `stallStates` + `pendingDispatchRoles`
  registries are now cleared by `resetSwarmState()` (via a new `resetExecutionStallState()` export),
  mirroring the route-invalidation precedent. The Task-dispatch path arms an episode that previously
  survived reset and denied later sessions' allow-legs at the 60-call threshold with an empty error
  message.
- `src/hooks/delegation-gate.ts`: `validateCoderReviewerAcceptanceField` now strips Cc/Cf code points
  before the emptiness check (U+200B no longer counts as content), and the gate now also requires some
  field to independently satisfy the validator so a bare `ACCEPTANCE:` header cannot borrow the
  next field's text (including the lone-CR spelling). Behavior change: a split-field dispatch that
  previously passed is now rejected with `acceptance_field_empty`, or injected when
  `hooks.auto_inject_acceptance` is on. Other Unicode filler (for example Lo/Mn characters such as
  U+3164) still counts as content, as before.
- `tests/helpers/isolated-test-env.ts`: corrected the docblock that claimed `os.homedir()` ignores
  `process.env` under Bun (falsified on Bun 1.3.14: it follows a redirected HOME/USERPROFILE on Windows but not on POSIX).
- `tests/unit/hooks/guardrails-native-agents.test.ts`: uses a sandboxed temp root per test instead of
  `os.tmpdir()` itself, so it no longer writes `%TEMP%\.swarm\session\shell-audit.jsonl` and
  destabilizes every later bun process on the host.

New tests: `tests/unit/hooks/execution-stall-reset-state-3608.test.ts`,
`tests/unit/helpers/isolated-test-env-homedir.test.ts`,
`tests/unit/hooks/delegation-gate-acceptance-validator-hardening.test.ts`.

## Why

The #3608 pollution was a real test-infra wedge: every session whose blast-radius census included
the affected suites re-paid a ~10-minute classification cost and risked misattributing the 17-58
failures to its own delta. The #3381 items were verified fail-open conditions (validator returning
`{valid:true}` on zero-width content and on field-borrowed headers) on a pre-dispatch gate. Both
issues are collated into one PR.

# Acceptance auto-injection: test coverage and docs precision

## Summary

- Pins four behaviors of `hooks.auto_inject_acceptance` found by a post-merge mutation pass over #3369: an injection from an unregistered session queues no advisory, a rejected no-text-field dispatch is left with exactly its original keys, the advisory carries the `acceptance_field_empty` reason, and an empty header that only the cross-field join can see is rejected and left untouched.
- `docs/configuration.md` now states precisely when the strict rejection stands (the injection cannot be applied to the field the validator inspected, or an injected default fails re-validation and is rolled back), instead of only "no field can carry the block".

## Known caveats

- No runtime behavior changes. The last pinned case is the behavior after the #3381 cross-field join hardening.
