# SQLite durable-state foundation and low-risk store migration

## Summary

Establishes `.swarm/swarm.db` as the durable-state foundation (issue #2480, Workstream D PR 1 of 8):

- **Canonical connection identity** — one cached handle per canonical project root (case-folded on Windows, symlink/8.3-collapsed via realpath), with a clean close lifecycle: best-effort TRUNCATE→PASSIVE WAL checkpoint on close, a `dispose` hook, and a process-exit close backstop.
- **Explicit support floors + driver-parity contract** — `engines` now declares `node >= 22.13` alongside `bun >= 1.3.13`; the loader produces a clear floor diagnostic on older Node; a shared parity-contract suite pins the bun/node behavioral deltas (the #1873 SQLITE_RANGE strictness is modeled by the test fake under Bun and exercised for real in the merge-queue smoke job on three OSes).
- **Versioned single-statement migrations with failed-migration recovery** — v14–v17 add `migration_failures`, the `insight_candidate` event stream (+ pending partial index), and the `phase_report` entity table; failures roll back, are recorded (table row, or a marker-file fallback when v14 itself fails), and retry on the next open; diagnose reports them.
- **Idempotent legacy import** — `.jsonl`-present + table-empty → one-txn import → `.imported` cold-archive rename; crash windows are retry-safe and legacy files are never silently destroyed.
- **Per-table durability classes** — `synchronous=FULL` for terminal-state tables (`qa_gate_profile`, `task_checkpoint_receipt` — production-wired through their write paths) and NORMAL for telemetry/operational tables; any batch containing a full-class op runs at FULL.
- **Health policy** — `quick_check` in `/swarm diagnose` (size-capped, reports driver floors and migration failures), VACUUM INTO backup at `/swarm close` (round-trip test), documented WAL-checkpoint/busy_timeout policy, typed disk-full/read-only/corrupt handling with a queue-retaining group-commit writer.
- **Retention-registry redesign** — the check now enumerates the swarm.db store-op seam (every durable store mutation is a named function), confines raw `Database`-handle usage outside `src/db/**` to an allowlist, and reverse-staleness-checks `src/db` foundation writers — DB-mediated writes can no longer bypass the registry invisibly.
- **First low-risk migrations through the four table patterns** — insight candidates (append-only stream + dual-contract consume txn + DELETE-based retention) and both drift-report families (entity/KV), replacing the legacy `.swarm/insight-candidates.jsonl`, `drift-report-phase-{N}.json`, and `doc-drift-phase-{N}.json` files (imported once, then cold-archived).

## Non-goals / later PRs

Plan ledger (D5), coordination state (D2), observability streams incl. skill-usage (D3), residual streams (D4), and human-facing artifacts stay files. Full policy doc: `docs/sqlite-durable-state.md`.
