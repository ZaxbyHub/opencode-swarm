- **Provenance:** compiled 2026-09-30 for issue #3004 / ADR-0003 against `@opencode/plugin@2.0.20` d.ts (dist/promise/*), `@opencode/schema@2.0.20`, `sst/opencode` v2.0.20 host source, and the official migration guide (opencode.ai/v2/docs/build/plugins/migrate-v1/). Adapter implementation: `src/host/v2/`.
- **Delta additions (2026-09-30 feedback closure):** row 9's compaction-customizer delta and row 5's template-substitution delta also apply to the release fragment's known-deltas list; row 14's mapping was corrected (execution.failed now maps to session.error, which v1 consumers actually read).
- **Rule:** every v1 surface the plugin registers has exactly one row with its v2 destination or an explicit `no equivalent` disposition. Rows marked **delta** document an intentional behavioral difference.

## ToolContext synthesis (v2 → v1)

The v2 tool context (`{sessionID, agent, messageID, id, signal, progress}`) is bridged to the full v1 `ToolContext`: `directory`/`worktree` = project root captured at setup (invariant 4 — never `process.cwd()`), `abort` ← `signal`, `metadata({title?, metadata?})` → `progress` (argument shape mapped), `ask` → the v2 permission domain: assert-first when `permission.assert` is available (2.0.29+; resolves = allow, rejects = deny; input `{sessionID, agent, action, resources}` with the host's normalizeAction table), else — on reply-only hosts (2.0.26 pin) — DENY on any `reply` resolution (`reply` is the answer-side RPC, not an ask surface; #3351 recorded decision), and fail-closed with no permission domain. Regression: tests/unit/host/v2/permission-bridge-fail-closed-3327.test.ts. Regression test: `tests/unit/host/v2/dual-shape-parity.test.ts` (third test - directory injection via the `src/host/v2/tools` `_internals` seam).

## Part-kind mapping (messages chain)

Text parts map 1:1. Non-text v2 content kinds (`media`, `tool-call`, `tool-result`, `reasoning`, `step-start`, `compaction`, `effort`) are preserved untouched on their message — the v1 chain's steps only read and write `type === 'text'` parts (verified against the composed steps' part-type reads). Unmappable kinds would be counted in a bounded debug log and get a row here; currently none.
