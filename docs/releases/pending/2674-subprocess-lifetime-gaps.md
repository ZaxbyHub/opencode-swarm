# Subprocess lifetime bounds for the last three unbounded git callers (#2674)

`writeProjectIdentity` (`getGitRemoteUrl`), `/swarm diagnose`'s Git Repository check (`checkGitRepository`), and the `complexity_hotspots` tool (`getGitChurn`) previously spawned git with no timeout, piped stdin, unbounded output, and no cleanup — a hung, signal-trapping, or pipe-holding child could freeze the calling host indefinitely, and a timeout kill on the churn path would have surfaced as a fabricated empty success.

All three now carry the full bounded contract (issue #2674): 5 000 ms sync timeouts with POSIX SIGKILL escalation, a 10 000 ms caller-owned race deadline plus tree-kill on the churn path, stdin ignored, output bounded (64 KiB sync caps; 5 MiB churn cap) or ignored outright, and explicit child env with `GIT_TERMINAL_PROMPT: '0'` (also restoring live-env semantics under Bun's process-start env snapshot). Failures stay structured and honest: the diagnose row renders `⬜ git state unknown` on timeout instead of a false "Not a git repository", and churn kills surface the tool's `error` JSON. Pinned by new adversarial suites (`identity-subprocess-bounds`, `diagnose-git-repository-subprocess-bounds`, `complexity-hotspots-subprocess-bounds`) that drive the real functions against a real fake-git executable across normal/hung/trapping/EOF/overflow/fork/nonzero/missing controls, and by the per-caller contract table in `docs/engineering-invariants.md` §3.
