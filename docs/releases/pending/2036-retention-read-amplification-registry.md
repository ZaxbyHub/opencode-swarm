## Complete retention registry for every durable stream; new durable writers now fail CI until registered

Before this change, retention policy for the ~190 durable-write call sites under `src/` was defined piecemeal — each module owned its own constants (or none), with no single artifact naming every stream's bounds, read amplification, close/archive lifecycle, owner, and final disposition. Full-file readers scaled with history with nobody accountable for the bound, and a new durable stream could be added with no review surface forcing a retention decision.

**One registry, machine-checked.** `scripts/retention-registry.data.ts` now records all 98 durable stream families under `.swarm/` and the platform-data roots — path grammar, canonical root, writer and reader symbols with citations, schema/version, state class (authoritative / operational / derived-rebuildable / governed content), privacy class, byte/age/count limits with global-vs-per-trigger scope, read bounds with sync/async behavior, lock and crash model, close/archive/reset policy, legacy compatibility, health signal, owner, and a completed disposition. The ratified document is `docs/observability-retention-registry.md`, with the enumeration evidence (commands + counts) committed as its appendix.

**A CI gate, not a snapshot.** `bun run check:retention` (a hard-fail quality step right after `check:events`) enumerates every durable-writing module under `src/` — write APIs, atomic-write helper calls, and SQLite open/acquire seams — and fails the build when a writer has no registry row, when a plumbing exemption goes stale, when a disposition is a placeholder (`TBD`/`deferred`/`future issue` are rejected), or when a citation points at a file that no longer exists. A newly added durable writer can no longer bypass a retention decision.

**Every row ends in exactly one of three dispositions.** Fix-in-issue rows link the already-open implementation issues (#2037 context telemetry, #2038 skill usage, #2039 core events, #2040 shell audit, #2041 PRM trajectories, #2042 PR subscriptions, #2045 lane sidecars, #2046 council attempts). Retain-by-design rows cite their durability requirement (plan ledger, knowledge receipts, evaluation substrate, close archives, hive quarantine). Not-a-defect rows carry the source proof (compaction bounds, FIFO caps, batch-scoped artifacts). One new sequence-amendment issue (#2309) was opened for the verified-unbounded residual streams no existing issue covers — knowledge retractions, unacknowledged criticals, curation proposals, consolidation and run logs, context snapshots, epic/turbo state, skill-improver and skill-optimizer artifacts, capsules, summaries, the repo-graph fingerprint close-orphan, PR-review run artifacts, review receipts, and doc-drift signals — unblocking PRs 09–23 on a complete, honest matrix.
