## What changed

The PR_REVIEW workflow now settles coverage truthfully at any N of 6 instead of trapping every partial outcome (issue #2383, third of the #2380 series):

- **Terminal N-of-6 settlement.** The exact-five partial-coverage trapdoor is gone. Every base dimension ends in exactly one normalized state (`COVERED`, `FAILED`, `CANCELLED`, `NOT_LAUNCHED`); completion requires every launched lane terminal or explicitly cancelled. `write_pr_review_artifact` admits `partial_base_coverage: { unresolved_dimensions: [...] }` for any N (the declaration must exactly match the gate-derived terminal settlement), persisted as a versioned v2 disclosure with per-dimension terminal states, typed reasons, and lane/batch identity. Legacy singular disclosures normalize on read and are never rewritten. `complete_pr_workflow` for PR_REVIEW now requires a `report_verdict` and enforces the matrix: COMPLETE may APPROVE / REQUEST_CHANGES / INCOMPLETE; PARTIAL only REQUEST_CHANGES or INCOMPLETE; NO_COVERAGE is a forced-INCOMPLETE operational report (it skips the findings ladder — nothing exists to validate — and appends one bounded `pr_review_no_coverage_terminal` audit event). A partial or zero-coverage report can never approve or claim a full review; validated findings from covered dimensions remain publishable.
- **Typed critic routing.** Reviewer `[REVIEWED]` rows now carry `risk_impact` (`ORDINARY` / `HIGH_IMPACT` / `UNKNOWN`) and `risk_tags` (`SECURITY`, `AUTH_PERMISSIONS`, `STATE_INTEGRITY`, `WRITE_PATH`, `EVIDENCE_INTEGRITY`, `GIT`, `CONFIGURATION`); `[CANDIDATE]` rows gained the same optional trailing fields. One shared production predicate (`prReviewFindingRequiresCritic`) now decides critic routing for inventory, artifact validation, and coverage admission: CRITICAL/HIGH always route; a MEDIUM routes only when `HIGH_IMPACT` or it carries any tag; `UNKNOWN` always routes; an ordinary MEDIUM with no tags does not. Paths, dimensions, keywords, and prose never override the typed values. Every newly written CONFIRMED finding must supply both fields (the write boundary rejects otherwise, and unknown tag values fail the row); legacy persisted findings normalize to `UNKNOWN` / `[]` at the single read boundary and therefore fail safe to critic review.
- **Audited armed recovery.** `abort_pr_workflow` gains `kind: "armed_recovery"`: the identity-correlated escape for a publication-armed workflow whose exact publication cannot proceed. It requires the exact bound head SHA, the staged authorization's revision digest, and the current gate generation (stale/foreign/mismatched requests fail closed; there is no force variant), settles remaining lanes first, appends exactly one bounded `pr_workflow_armed_recovery` audit event, invalidates the staged publication authorization, and leaves a recoverable terminal state that preserves validated work — the controller can re-arm after repair or abort cleanly. A corrupt (unreadable) armed record still has no tool exit and requires the existing manual recovery.
- **Correlated reviewer re-entry.** Direct Task dispatches of `reviewer` / `test_engineer` may bypass the generic Stage-A task-workflow requirement ONLY through a new one-use authorization issued by `authorize_pr_review_reentry` (bound to session, workflow, run, head SHA, worktree revision digest, role, and gate generation; 10-minute TTL; atomic consume; replay, cross-session, wrong-role, expiry, and any workflow progress fail closed). No prompt-text inspection is involved; the council gate, background-task block, and every other delegation check remain authoritative.

## Who cares

Anyone whose PR review lost validated work to a partial-coverage wedge (#2375 incident class), waited on unnecessary critic routing of ordinary MEDIUM findings, or got trapped in an armed publication state.

## Upgrade notes

Reviewer and candidate lane-output row grammars gained trailing fields; legacy rows parse unchanged (normalized fail-safe at the single boundary), but in-flight pre-upgrade critic batches may drop claims after a reviewer re-run and require the normal bounded re-dispatch. `complete_pr_workflow` for PR_REVIEW now requires `report_verdict`. Skill guidance (`swarm-pr-review`) now directs the controller to settle N-of-6 truthfully instead of aborting.
