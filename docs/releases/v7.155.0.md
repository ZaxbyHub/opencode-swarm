- Add an opt-in indexed storage mode for the repository dependency graph. Set `repo_graph.storage` to `'indexed'` to maintain a derived `.swarm/repo-memory.sqlite` index alongside `.swarm/repo-graph.json`, accelerating bounded neighbourhood lookups (coder localization, reviewer blast-radius, memory-reflection anchor resolution on repositories whose graph exceeds the reflection read budget). `.swarm/repo-graph.json` remains authoritative in both modes; the default stays `'json'` (unchanged behavior), a stale or corrupt index silently falls back to the JSON path, and `.swarm/repo-memory.sqlite` can always be deleted safely — it is rebuilt on the next graph save. `/swarm close` archives and cleans `repo-memory.sqlite` the same way it already handles `swarm.db`. Indexed mode is not a blanket speedup: cold neighbourhood reads get much cheaper, but each graph save costs roughly a third more, and a prompt turn that also needs the whole graph right after a graph change pays a small extra cost. The index is built by the next graph save after you enable the mode (for example `repo_map action="build"`); until then reads transparently use the JSON path.

Add `bun run check:registry-citations`, a CI gate that stops `file:line` citations in `scripts/retention-registry.data.ts` from silently drifting. The structural arm hard-fails on citations naming a missing file, an out-of-bounds line range, or a malformed no-colon shape; the anchor arm checks that the identifier written next to a citation actually occurs in the cited lines, ratcheted against `scripts/registry-citation-baseline.json` so pre-existing drift is frozen and may only shrink. Pre-existing anchor drift in 40 other registry rows (111 citations, including five naming symbols that no longer exist anywhere in the file they cite) is frozen in that baseline so it is visible and can only shrink. It is not fixed wholesale here, with one exception: where this change already had to edit a citation line, the inaccuracy on that line was corrected rather than left standing.
