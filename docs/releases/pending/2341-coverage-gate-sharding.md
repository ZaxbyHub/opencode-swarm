# CI: shard the merge-queue coverage gate and raise the queue timeout — green PRs no longer evicted by `checks_timed_out` (#2341)

## What changed

The merge-queue coverage gate is no longer one ~45-minute serial job racing the queue deadline. It is now a 6-way shard matrix plus a small fail-closed merge job, and the merge queue's check-response timeout is raised from 60 to 90 minutes.

- **Eviction root cause.** The `coverage` required check ran the entire gated test suite (~2700 files) one `bun test --isolate --coverage` process at a time in a single job (~45 min clean). The merge queue's `check_response_timeout_minutes: 60` clock starts at **enqueue**, not when checks start, so a PR queued behind another entry lost part of its budget to queue wait: PR #2313 — all 35 PR-event checks green — was evicted at 60.6 minutes with reason `checks_timed_out`, twice. The earlier CI-004 fix (PR #2290 era) had stopped serializing coverage behind the `unit` matrix but left this single serial unit as the group's long pole.
- **New graph.** `coverage-shard` (matrix of 6, ubuntu, `timeout-minutes: 30`, `fail-fast: false`) partitions the gated test list with the same round-robin formula as the `unit` job, so coverage shard N measures exactly the file set of `unit (ubuntu-latest, N)` and a failing shard maps 1:1 onto a unit shard. Each shard concatenates its per-file lcov into a uniquely named part artifact. The `coverage` merge job (name unchanged — the required-check context in ruleset 17809658 stays byte-stable) downloads all parts and runs `scripts/ci/finalize-coverage-gate.sh`, which merges them via `merge-lcov.mjs` and enforces the threshold once. Expected critical path drops from ~45 min to ~12–15 min after `quality`, at any queue position.
- **Fail-closed merge (acceptance criterion).** The finalize script checks, in order: the shard matrix's aggregate job result must be `success` (a failed, skipped, or cancelled shard fails the gate even if it managed to upload a partial part); exactly `EXPECTED_SHARDS` part files must be present; every part must be non-empty and contain at least one `DA:` record; only then merge and enforce. There is no path where a missing shard report silently lowers the measured coverage. The merge job uses `if: always()` (the established `unit-passed` pattern) so a shard failure produces a **red** required check rather than a missing one — a missing required check reproduces the same `checks_timed_out` eviction.
- **Gate semantics unchanged.** Same threshold (`COVERAGE_THRESHOLD`, default 65.00 — unchanged since the #1778 H4 recalibration; see the docs correction below), same max-merge LCOV union (merging 6 concatenated shard parts computes the same value the per-file-part merge did), same per-file `bun test --isolate --coverage` measurement with bounded retry (issue #1712 isolation preserved), still merge-queue-only and skipped for release-please branches.
- **Ruleset changes (settings, applied at PR time).** Ruleset 17809658 was updated via the GitHub API with before/after diffs: (1) `merge_queue.parameters.check_response_timeout_minutes` raised 60 → 90 — deliberately first, so currently-queued PRs stop evicting while the sharding PR is in review; the two parts compound (90 minutes covers deep-queue wait, sharding cuts the gate's wall-clock ~3x). (2) `unit-passed` added to required status checks: analysis of the observed eviction showed its literal trigger was a failed `unit (macos-latest, 1)` cell — the group was already red, but required `integration`/`smoke` checks were *skipped* behind it and never reported, so the queue could only sit and expire the full window (`checks_timed_out`). Requiring `unit-passed` (an `if: always()` aggregate that mirrors this PR's `coverage` merge job) fails such a group immediately with `checks_failed` instead of burning the window.
- **Six shards, not 3 or 8.** Six keeps per-shard file counts (~450) at parity with the `unit` job's ubuntu cells (the mapping property above), leaves >2x headroom in the 30-minute per-shard timeout for bounded-retry storms, and adds only +5 concurrent jobs on a public repository. Merge-queue builds run one group at a time and each group's `gh-readonly-queue/...` ref gets its own workflow-concurrency key, so groups never serialize behind each other.
- **Structural guard extended (acceptance criterion).** `tests/unit/scripts/ci/coverage-shard-graph.test.ts` pins the new graph — shard matrix cardinality, `needs` wiring on both jobs, `if: always()`, artifact handoff, the cross-check that matrix length === `SHARD_COUNT` === `EXPECTED_SHARDS`, partition parity with the `unit` job, and the fail-closed check order — so a future edit cannot re-serialize the long pole (the CI-004 regression class). `tests/unit/scripts/ci/finalize-coverage-gate.test.ts` executes the real merge script against fixture shards for the fail-closed matrix (missing / empty / header-only part, failed shard result, threshold breach, override).

## Why

Both root causes from the issue were required: a 60-minute deadline was structurally insufficient at any queue position other than 1, and an indivisible 45-minute serial job meant no timeout value could fix position-dependent evictions. Shard wall-clock ~12–15 min + merge ~2 min + `quality` fits with margin even behind deep queue wait under a 90-minute budget.

## Migration steps

None for local workflows. The ruleset timeout change is already applied (settings, verified by API diff). The required-check list is untouched — `coverage` remains the single required context, now reported by the merge job.

## Known caveats

- Real queue behavior can only be validated by an actual merge-group run after merge (the shards run only on `merge_group`); PR-event CI skips both jobs' steps as before.
- Stale docs corrected alongside: `TESTING.md` and `contributing.md` claimed a 41.48% threshold — stale since the #1778 H4 recalibration to 65.00. Older release fragments mentioning 41.48% describe the pre-#1778 `tests/unit`-only era and are historical snapshots. Quarantine guidance in the swarm-ci-monitor skill now points at `scripts/ci/finalize-coverage-gate.sh`, where the threshold lives.
- Six shards re-pay checkout/install/build per shard (~4 min each); the net wall-clock is still ~3x better than the serial job, and runner time on a public repo is free.
