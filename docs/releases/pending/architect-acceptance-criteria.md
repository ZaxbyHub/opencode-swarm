# Make the runtime architect reliably emit ACCEPTANCE on every coder/reviewer dispatch (architect-acceptance-criteria)

#1687 wired a blocking `ACCEPTANCE_FIELD_REQUIRED` gate into the coder/reviewer Task-dispatch path, but its release note admitted "no live end-to-end exercise of a real delegation." In real swarms the runtime architect consistently omitted the `ACCEPTANCE:` line, so its coder/reviewer/council dispatches were blocked pre-dispatch with `ACCEPTANCE_FIELD_REQUIRED` (notably the council-reviewer dispatch shown during paid-swarm phase 1). Root cause was prompt-effectiveness, not a missing string: the rule existed at `src/agents/architect.ts:397` but was a 95-word run-on sentence buried 130 lines above the DELEGATION FORMAT block, the two delegation examples used abstract placeholder brackets instead of a concrete filled-in line, and every operational skill that constructs a coder/reviewer Task dispatch was silent on ACCEPTANCE.

## Changes

- **`src/agents/architect.ts` — ACCEPTANCE FIELD RESOLUTION rule strengthened.** Replaced the run-on sentence at line ~397 with a header-led numbered block (`ACCEPTANCE FIELD RESOLUTION — REQUIRED on every … Task dispatch`), a 3-step resolution procedure, an explicit "never empty" rule, and a disambiguation note that the plan-task `acceptance` field is a different concept from the per-dispatch `ACCEPTANCE:` line. The two delegation examples (coder + reviewer) were rewritten with a concrete `ACCEPTANCE: FR-007 …` value instead of the `[copied verbatim from spec.md, or …]` placeholder, and a NOTE line after the examples documents the task-derived DONE-restatement form separately so meta-commentary does not leak into the field value. All existing assertions in `architect-prompt-template.test.ts` (#31–#38) stay green because the asserted substrings are embedded verbatim in the new wording; three new assertions (#39 concrete coder example, #40 concrete reviewer example, #41 disambiguation note) guard against regression to the placeholder shape.
- **`src/agents/architect.ts` `buildCouncilWorkflow` — inline `{{COUNCIL_WORKFLOW}}` block.** The inline council-dispatch block (always visible when `council.enabled === true`) dispatches a gated reviewer member at both STEP 1 sites (task-scoped and phase-scoped) but had zero ACCEPTANCE mentions; a model following the more-local inline block could omit the line. Added a `→ REQUIRED:` line at each STEP 1 naming only the `reviewer` member as gated (test_engineer/critic/sme/explorer are not gated by `delegation-gate.ts:2014`), with phase-scoped resolution wording at the phase STEP 1.
- **`.opencode/skills/execute/SKILL.md` — 5 delegation-construction sites.** Added `→ REQUIRED:` reminders at the retry template (which previously *guaranteed* re-trigger of ACCEPTANCE_FIELD_REQUIRED on retries), step 5b (coder), step 5j (reviewer), step 5j-COUNCIL (council reviewer member — matches the screenshot symptom), and step 5k (security-reviewer; the gate does not exempt security-only reviews). All additions are continuation lines (`→ REQUIRED:`) appended after the existing step header so the `/^\s*5n\./gm` count and sibling slicings stay intact.
- **`.opencode/skills/phase-wrap/SKILL.md` — 2 council dispatch sites.** Steps 5.65 (phase council) and 5.7 (final council) each dispatch a gated reviewer member; both gained a `→ REQUIRED:` continuation line.
- **`.opencode/skills/brainstorm/SKILL.md` — 1 spec-review dispatch.** Phase 5 dispatches the canonical reviewer for spec review (pre-plan, no fr_refs); gained a `→ REQUIRED:` line with task-derived DONE-restatement resolution wording.
- **`.opencode/skills/swarm-plan/SKILL.md` — save_plan fallback template.** The literal `TASK:/OUTPUT:/INPUT:/CONSTRAINT:` fallback template (used when `save_plan` is unavailable) gained its own `ACCEPTANCE:` field — plan-writing has no fr_refs so a DONE restatement is correct.
- **`.opencode/skills/swarm-pr-feedback/SKILL.md` — direct-Task carve-out.** The 1-file direct `Task(subagent_type="<coder>", ...)` carve-out gained a `→ REQUIRED:` line noting the dispatch must still carry `ACCEPTANCE:`.
- **Byte-identical mirrors updated.** `.claude/skills/{brainstorm,plan}/SKILL.md` use the byte-identical mirror pattern (`canonical: '.opencode'`) and were updated to match; `.claude/skills/{execute,phase-wrap,swarm-pr-feedback}/SKILL.md` are thin adapter shims and needed no change. Bundled mirrors (`.swarm/bundled-skills/...`) are runtime-synced from `.opencode/` and were also updated to keep local runtime correct.
- **Tests.** Four new structural regression test files pin every delegation-construction site so the silence cannot silently return: `execute-acceptance-coverage.test.ts` (6 cases including 5k), `phase-wrap-acceptance-coverage.test.ts` (3 cases), `brainstorm-acceptance-coverage.test.ts` (1 case), `plan-and-feedback-acceptance-coverage.test.ts` (2 cases). `architect-prompt-template.test.ts` extended with 3 cases; `architect-council-prompt.test.ts` extended with a 3-case ACCEPTANCE-on-council-dispatch describe block. New tests use line-anchored regexes, sliced sections, and a global ACCEPTANCE floor count (not bare-token presence) so they cannot false-pass.

## Known caveats

- **Structural-only verification, same as #1687.** These tests prove the prompt and skills now contain the required strings and concrete examples; they do not prove a live LLM emits `ACCEPTANCE:` at runtime. The substantive improvement over #1687 is that the rule is now (a) header-led and concrete, (b) repeated at every delegation-construction site the gate covers, and (c) guarded by structural regression tests. There is still no automated live-LLM-dispatch test.
- **Drift-checker false-positive surface.** After this change, `bun run drift:check` reports ~26 skill-assertion findings against brainstorm and plan. All are false positives from the drift checker's heuristic blind spots: it does not distinguish `.not.toContain` from `.toContain` (so phrases that are *supposed* to be absent are flagged as missing), it treats fixture strings inside its own self-test template literals as real assertions, and it misattributes assertions to the wrong skill file. All named test files pass when actually executed (237/237 across 15 files). The local drift checker is soft-warn by default; CI runs it with `--enforce`; 0 mirror-parity findings. This is a pre-existing latent bug in the drift-checker heuristic, not introduced by this change; out of scope here.
- **Pre-existing latent gap (unchanged):** a coder/reviewer dispatched via `dispatch_lanes_async` bypasses the Task-only gate at `delegation-gate.ts:1949`. The architect prompt already prohibits advisory-lane usage for coder/reviewer; not the bug fixed here.
