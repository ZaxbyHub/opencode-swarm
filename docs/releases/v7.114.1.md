## Why
The skills are runtime protocol documents consumed by AI agents. When they describe APIs/paths/tokens that no longer exist or never existed, agents following them produce broken commands, miss real defects, or attempt unavailable capabilities. This sweep re-aligns every skill with the current code. Sequencing-critical items (MIC-1 ci-simulate contract, GPT-10/11 worktree base + guardrail bypass) MUST land before PR-3 (reachability wiring), which is why this PR merges first.

## Migration
None. No runtime behavior changes for end users; the only `src/` behavior change is removal of the dead `allow_full_suite` Zod arg (already ignored by the env-only runtime gate) and removal of `--preset` advertising from council help (parsing/emission kept).

## Breaking
None. No public API changes. The `allow_full_suite` arg was already documented as "intentionally ignored" and the runtime is env-only.

## Caveats
- This is PR-1 of 6. PR-2 owns `swarm-pr-review/SKILL.md` (canonical) and `execute/SKILL.md`. PR-3 does reachability wiring. PR-4 adds drift-check parity tests. PR-5/6 cover structural splits and gate-integrity code.
- The OPS-1 subcommand list and `<loop-complete/>` marker grammar assertions are parity-tested in PR-4, not here.
- `drift:check` stays green at the enforcement level (it is soft-warn by default). This PR introduces 180 soft-warn findings from `check-skill-assertions`; all are proven scanner false positives (test-fixture strings and runtime-output assertions misattributed to changed skill files) — every cited test file passes when run individually. The parity-test hardening that will silence these scanner FPs is owned by PR-4. All byte-identical pairs remain byte-identical.
