# Skills Quality Audit — PR-3/6 Reachability Wiring

## What changed
PR-3 of the 6-PR skills quality audit. Wires the 7 bundled skills that shipped to npm consumers but were unreachable by any automatic mechanism (finding XC-1): `ci-failure-batching`, `merge-queue-readiness`, `gate-attribution`, `skill-edit-validation`, `worktree-retry-cleanup`, `test-file-split`, `swarm-ci-monitor`.

- **Strategy B trigger-point references** — added a one-line `file:.swarm/bundled-skills/<slug>/SKILL.md` reference from each skill's relevant workflow step: `swarm-pr-feedback` → `ci-failure-batching` (Batch Collection); `commit-pr` → `merge-queue-readiness` (Merge queue section) and `skill-edit-validation` (Step 0 hygiene, conditional on a SKILL.md edit); `swarm-ci-monitor` → `merge-queue-readiness` (pre-Step-4, noted as optional and additive to Step 3's live re-checks); `execute` → `gate-attribution` and `worktree-retry-cleanup` (Stage B gate section); `writing-tests` → `test-file-split` (FR-006 section, also closing MIC-15's missing forward reference); `editing-skills` → `skill-edit-validation` (Step 5 validate-and-publish, dev-repo contributor surface).
- **`swarm-ci-monitor` entry point** — added a full `/swarm ci-monitor <pr-url|owner/repo#N|N>` command (`src/commands/ci-monitor.ts`), a `### MODE: CI_MONITOR` architect stub, a TUI shortcut, and docs (`docs/commands.md`, `README.md`, `.claude/skills/swarm/SKILL.md`). Previously the skill had `disable-model-invocation: true` and no command, MODE stub, or help entry — the preferred (command+stub) option from the issue, not the minimal documented-invocation fallback.
- **Corrected false documentation** — `docs/skills.md:13` no longer claims all shipped protocols load via `/swarm` MODE dispatch; it now describes both real mechanisms (MODE dispatch for most skills, explicit `file:` trigger-point references for the playbook/support skills). `docs/releases/pending/playbook-skills-from-session-1685.md` lines 11/17 corrected to match the actual wiring (4/5 playbooks referenced from mode skills, `skill-edit-validation` from `commit-pr`/`editing-skills`; no automatic keyword-scoring or hook injection — `.swarm/bundled-skills` stays excluded from `SKILL_SEARCH_ROOTS` by design).
- **`ci-fix-monitor` fold-ins (MIC-13)** — removed the false "generated by skill-generator, edits preserved on regeneration" banner and the generated-skill frontmatter (`triggers`, `generated_from_knowledge`, `source_knowledge_ids`, `generated_at`, `confidence`, `status`, `version`, `skill_origin`); verified `src/services/skill-generator.ts` rejects regeneration for any `BUNDLED_PROJECT_SKILLS` slug, so the banner described an unreachable code path. Added a `src/config/skill-mirrors.ts` contract for the previously-uncontracted `.agents/skills/ci-fix-monitor` twin — a new `adapter` kind (mirroring the existing `ADAPTER_ARCHITECT_MODE_SKILLS` check pattern, generalized to non-MODE skills that have no `.claude` copy). Added an OPS-8 standalone retry bound (5 fix-push cycles, then escalate) for direct invocation outside `swarm-ci-monitor`'s own composed loop.
- **Scanner false-positive fix (incidental, in-scope)** — `scripts/check-skill-assertions.ts`'s slug matcher used bare substring containment, so slug `"swarm"` collided with the ubiquitous `.swarm/` runtime directory whenever `.claude/skills/swarm/SKILL.md` was edited (required here for the `/swarm ci-monitor` help entry). Tightened to require a real `skills/<slug>` path segment. This is the exact false-positive class PR-1 documented as pre-existing and deferred to PR-4; fixing the specific mechanism here does not preclude PR-4's broader parity-test hardening.

## Why
Issue #1806 / XC-1: seven skills were shipped via `BUNDLED_PROJECT_SKILLS` and materialized into every consumer project's `.swarm/bundled-skills/`, but no automatic mechanism (architect MODE stub, `/swarm` command signal, or skill-search root) ever loaded them. `swarm-ci-monitor` — the PR-lifecycle chain's only merge authority — had no entry point at all.
