# PR workflow startup recovery and review-to-feedback transition

PR workflows now classify the repository's Git state before durable activation.
Unmerged index entries, in-progress Git operations, dirty submodules, unsafe
`.swarm` state, and indeterminate Git probes fail closed with one typed manual
recovery action instead of activating a gate and repeatedly attempting stash.
If such a state appears after activation, checkout preparation records a durable
recovery result, status reports the same classification, and automatic resumes
stop until the workflow is aborted or recovered.

The exact `/swarm pr-feedback <PR_URL> continue from
.swarm/pr-review/<run_id>/feedback-handoff.json` command now performs a
controller-owned lifecycle transition. It proves the active review is terminal,
validates the bounded handoff and final findings ledger, compares workflow
identity plus revision under the session lock, and atomically creates a fresh,
unbound PR_FEEDBACK gate. Exact retries are idempotent; mismatched, tampered,
escaped, stale, or nonterminal handoffs fail without clearing the review. The
later immutable feedback inventory must include every carried finding ID.

Configured PR-monitor automatic feedback also respects lifecycle ownership.
Events cannot inject feedback mode over an active review, and events that arrive
after a feedback inventory freezes are retained in a bounded durable queue for a
later round. When no workflow owns the session, automatic feedback establishes
the same mechanical gate before routing any fix work.
