## What changed

- **PR-monitor breaker survives snapshot-write failures (#2409):** `handlePollError` commits in-memory breaker progression *before* the durable error-snapshot write (now best-effort). Previously a deterministic `updateSnapshot` throw — e.g. the over-capacity store guard — escaped before `circuitBreakerMap.set`, so the breaker never tripped and every interval re-polled into the same failure.
- **Capacity refusals short-circuit to a skip state:** the store's over-capacity throw is now a structured `PrSubscriptionCapacityError`. It bypasses per-PR breaker accounting and enters a worker-level skip state that polls only a one-PR recovery probe (searched across the full active set, with idle backoff bypassed so recovery cannot starve); a successful probe write clears the refusal and full polling resumes without a restart. Refusal health counters advance exactly once per refused cycle, so `skippedPrCount` is a true skip tally (no discovery-cycle overcount). `/swarm pr status` prints a `Monitor:` footer disclosing the refusal (with skip/cycle counts and the archive/split remedy) and circuit-suspension count; refusal enter/clear emit always-visible advisories.
- **Per-PR poll consolidation (#1660):** one `gh pr view --json number,state,mergeable,mergeStateStatus,headRefOid,statusCheckRollup,reviewDecision,reviewRequests,comments` snapshot plus one `gh api pulls/N/comments` call replace the previous three pr-view spawns and two gh api spawns per PR per poll (5→2, 6→3 while queued). Conversation-comment ids keep the REST numeric id space via the `#issuecomment-<id>` permalink (node-id fallback), so existing `lastCommentId` markers keep matching.
- **Coder-settlement recovery errors enriched (#2202):** `CODER_SETTLEMENT_RECOVERY_UNCERTAIN` (3 sites) and `CODER_SETTLEMENT_MERGE_RECOVERY_REQUIRED` now name the task, owning transition, WAL path, WAL state, merge outcome and the exact `Run /swarm recover <task> (or /swarm reset-session)` command — never WAL-deletion advice.
- **`/swarm diagnose` names the exact reset command (#1896 row 4):** the Invocation-circuits check lists each open circuit's digest and count plus the copy-pasteable `/swarm guardrail reset <digest> --invocation <id>`, capped at 3 with `+N more`. `/swarm reset-session` now releases the invoking session's guardrail circuits (audited; foreign sessions untouched).
- **`auto_checkpoint_threshold` schema description corrected:** now describes the completed-task auto-save trigger; retention wording moved to `max_retention` where the behavior already lived.
