# WAL-consistent /swarm close SQLite archives

## What changed

- **In-process `VACUUM INTO` snapshot** (`src/commands/archive-sqlite.ts`, new):
  `/swarm close` now archives `swarm.db` by taking a transactionally consistent
  single-file snapshot via a dedicated connection through the shared
  `src/db/sqlite-loader.ts` loader, instead of copying only the main `.db` file.
  The snapshot contains all committed rows (including those still in the WAL)
  and excludes rows from any concurrent uncommitted writer. The destination is
  validated read-only (`PRAGMA query_only = ON` + `integrity_check` + schema +
  row counts) and atomically published via temp-then-rename.

- **Removed external `sqlite3` CLI dependency** (`src/commands/close.ts`): the
  legacy `copySqliteSafe` (which shelled out to `sqlite3` for
  `wal_checkpoint(TRUNCATE)`, then raw-copied the main file) and its
  `_internals.spawnSync` wrapper are gone. The old raw-`copyFile` fallback lost
  committed WAL rows whenever the CLI was absent (common on Windows).

- **Structured archive result + `close_archive_result` telemetry event**
  (`src/commands/close.ts`, `src/telemetry.ts`): each archived artifact now
  produces a structured result (`requiredness`, `attempt`, `validation`,
  `source_disposition`, `method`, `reason_code`) collected in a single
  `archiveResults` array. The user-facing summary prose, the clean-stage gate,
  the failure map, and the new `close_archive_result` telemetry event are all
  derived from that one array, so they can no longer disagree. The event also
  carries `archive_valid` / `archive_empty` health facts (counts only — no row
  content is ever logged).

- **Truthful optional-absent vs required-failed** (`src/commands/close.ts`): an
  absent optional artifact (including `swarm.db`, which is lazily created) is
  now reported as `source_disposition: absent` and is silent, rather than
  rendered as an archive failure that obscures partial success.

- **Telemetry archive cut/order + flush** (`src/commands/close.ts`,
  `src/telemetry.ts`): the rotated `telemetry.jsonl.1` is now archived and
  cleaned alongside the active `telemetry.jsonl` (previously it was orphaned).
  The telemetry write stream is flushed (`flushAndDrainTelemetry`, awaiting the
  stream `finish` callback) before archiving, so buffered tail records are no
  longer silently lost.

## Why

`/swarm close` could archive a `swarm.db` that was a stale 4 KiB shell while the
live `swarm.db-wal` held every committed row — silent data loss in the archive
bundle. The external `sqlite3` CLI was also a forbidden external dependency
(AGENTS.md invariants 2/3), and the archive outcome was scattered across
booleans and prose strings that could diverge from any telemetry signal.

## How to use

No action needed. `/swarm close` and `/swarm finalize` now produce
transactionally consistent, validated SQLite archives automatically. Operators
can observe the new `close_archive_result` event in `.swarm/telemetry.jsonl` and
the `archive_valid` / `archive_empty` health facts.

## Migration

No migration required. Existing archive bundles created by prior versions are
unchanged; only newly-created archives benefit from the consistent snapshot.

## Known caveats

- `plan.json` and `plan-ledger.jsonl` remain `required` for the
  warning/result surface, but their deletion is still governed by the
  terminal-state unconditional-removal carve-out (plan-durability invariant):
  they are removed even on archive failure to prevent CLOSED-plan resurrection
  next session, with a truthful "no archive copy retained" warning. Deletion
  gating for all other artifacts remains with the archive-first guard.
- The `close_archive_result` event is emitted after the telemetry archive cut,
  so it appears in the live `.swarm/telemetry.jsonl` of the closing session
  (consumed by in-process listeners and subsequent sessions), not in the
  archived bundle's telemetry file.
