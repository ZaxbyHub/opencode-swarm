# Shell Write Gate: Directory State, Child-Scoped Chdir Wrappers, sh -c Payload (G1)

## What changed

- **Directory-state model for the write gate** (`src/hooks/shell-write-detect.ts`):
  the resolver walk now threads one `DirectoryState` (`{cwd, prevCwd, dirStack}`)
  through both passes instead of a bare cwd stack. `cd` word forms resolve-or-
  withdraw: bare `cd` / `cd ~` / `cd ~/x` land at `$HOME` (withdrawn when the
  line reassigns `HOME=`), `cd -` lands at the modeled `prevCwd` (withdrawn
  when unmodeled or `OLDPWD=` is reassigned), and dynamic operands (`cd $VAR`)
  withdraw later writes — the historical literal-append could fail OPEN under
  a broad declared scope. `pushd`/`popd` are tracked (push, bare swap, pop;
  `±N`/`-n`/stack-overflow withdraw), and `cd -P src` / `cd -- src` now track
  the real operand. Conditionals carry both outcomes explicitly: pipelines
  run components on isolated state copies with post-pipeline withdrawal,
  `if`/`case` branch copies diverge over the COMPLETE state (cwd + prevCwd +
  dirStack + withdrawal flag — #3567 feedback PRR-001) and withdraw, loops
  accept only a full-state fixpoint, and function bodies walk a discarded
  copy that inherits (never zeroes) the context withdrawal. Withdrawn writes reach the gate as
  `resolvedPath: null` with an additive `unresolved` marker; a withdrawn
  capability eval denies before any `evalDirectory` fallback (#3491 AC1/AC3,
  #3539 AC1/AC5).

- **Child-scoped env/sudo chdir through a quoted subshell transform**
  (`src/hooks/guardrails/destructive-command.ts`, `tool-before.ts`,
  `guardrail-explain-service.ts`): chdir-bearing wrapper segments
  (`env -C DIR`, `env -S '…-C DIR…'`, `sudo -D DIR`) rewrite at the gate as
  correctly-quoted subshells `( cd -- 'DIR' && <re-unwrapped inner> )`, so the
  wrapped command's writes resolve under the CHILD cwd while following
  siblings stay at the parent cwd (bash-true). DIR is emitted through a POSIX
  single-quote serializer (`'` → `'\''`); expansion-bearing operands
  (`$VAR`, `~`, `$(…)`, globs) are never serialized — the segment rewrites to
  a withdrawal form whose inner writes withdraw. Nested chdir wrappers
  compose as nested subshells. The destructive arm receives an evolving
  per-segment directory context (inner `cd`s tracked; unrepresentable
  mutations relocate to a deny-on-uncertainty sentinel), and
  `/swarm guardrail explain` shares the same preprocessing (#3491 AC2/AC4).

- **Shared `sh -c` payload extractor** (`src/hooks/guardrails/destructive-command.ts`):
  the payload is the single quote-removed word the `-c` flag selects (sh's
  argv[2] contract: the next standalone word after the flag cluster),
  extracted by a quote-aware tokenizer shared with the W2 serializer.
  Trailing positionals (`sh -c 'payload' sh`) and same-kind quote
  concatenation (`'\''`) no longer defeat the unwrap, and words after the
  payload ($0/$1…) are never scanned as commands (#3491 AC5/AC7).

- **Review round 1 hardening** (`destructive-command.ts`, `tool-before.ts`,
  `guardrail-explain-service.ts`): the uncertain-DIR withdrawal form uses a
  synthetic dynamic cd operand, so it withdraws UNCONDITIONALLY — the first
  round's synthetic `cd -` landed at a modeled `OLDPWD` after a preceding
  `cd`/`pushd` and admitted the wrapped writes. The destructive arm's
  child-cwd context is keyed per OCCURRENCE instead of per segment text
  (first-wins text keying let `env -C src rm -rf dist; env -C .. rm -rf
  dist` inherit the first occurrence's in-scope context). `/swarm guardrail
  explain` mirrors the gate's null-path decision tree — withdrawn/dynamic
  write targets answer block, and inspectable evals route through their
  tracked working directory exactly like the gate.

- **sh-family flag-cluster payloads** (`src/hooks/shell-write-detect.ts`,
  `src/hooks/guardrails/destructive-command.ts`; final-critic rounds 2–5):
  the covered grammar is bash-true, complete over four dimensions —
  [which letters are options] (clusters like `-xc`/`-ceu`; unknown letters
  are deny-on-uncertainty), [where arg-taking members draw arguments]
  (`o`/`O` take the next standalone word VERBATIM as their optname —
  `bash -eo pipefail -c …`, `bash -oc pipefail 'code'` — and a dash-led
  optname is erroring bash rc=2; cluster tails are always MORE option
  letters), [which word `c` selects] (`c` does NOT grab the next word
  verbatim: option parsing CONTINUES past it and the command string is the
  FIRST NON-OPTION word — `bash -c '-e' 'code'`, `bash -c -x 'code'`,
  `bash -c -o pipefail 'code'`, `bash -c -c 'code'` all execute the last
  word), and [`--` handling] (`--` and a lone `-` end option parsing; with
  a pending `c` the FIRST operand after the terminator is the command
  string, flag-shaped or not — `sh -c -- 'code'` runs; without one it is
  the script-file operand). Long flags are recognized only before
  short-option parsing starts (bash's "[GNU long option] [option]" order;
  `bash -c --rcfile F 'code'` errors rc=2 ⇒ deny-on-uncertainty). One
  shared invocation-flag walk feeds BOTH the dc wrapper extractor (heads
  may be path-qualified: `/bin/sh`) and `detectInterpreterEval`'s
  shell-family matcher. The earlier anchored `-c`-first spellings, the
  round-2 tail-as-payload rule, the round-3 o-branch tail-eating rule, and
  the round-4/5 verbatim-word rules all ADMITTED executing forms while
  real bash runs the payload; the anchored form also over-blocked benign
  multi-flag in-scope spellings. The tail-glued `-c'code'` and
  `-opipefail` spellings, unknown flags, a pending `-c` with no operand,
  and clusters sharing two or more arg-taking members (`-oc`, `-co`) are
  deny-on-uncertainty (the eval classifier fires, the wrapper never
  unwraps). Long `--rcfile`/`--init-file` keep the spaced next-word form
  (and the gate-tolerated `=value` gluing, valid only in the leading long
  phase). Python/perl/ruby cluster handling is untouched here — the W7
  per-interpreter cluster grammar (delivered in the G3 PR, not "PR-3")
  replaces this enumeration for those interpreters (`perl -i -pe`,
  `perl -i.bak -ne` now carry an interpreter_eval write alongside the
  in-place report; the G3 fragment is the operative description).

## Known edges

- `pushd ±N`, `pushd -n`, `popd ±N`, `;&`/`;;&` case fall-through, and
  `cd`/`cd -` with reassigned `HOME=`/`OLDPWD=` fail closed (withdrawal) by
  design — inherited shell state is unavailable statically.
- Control-flow bodies whose directory landings diverge over the complete
  state — now INCLUDING the withdrawal flag (#3567 feedback PRR-001: a
  withdrawn branch is divergence) — withdraw later writes instead of
  fabricating a merge; benign in-scope writes inside the body are unaffected.
- A `||` chain whose LEFT operand is not a statically-provable failed
  directory command and whose RIGHT branch moves directories now withdraws
  later writes (#3567 feedback PRR-012: the chain models both the skipped
  and the execute-from-pre-left outcomes; disagreement withdraws). The old
  skip-only model admitted `cd nope/sub || cd ../..; write` while bash ran
  the right branch; the new model over-denies `cmd || cd x; write` where the
  left is likely to succeed — fail-closed by design (both candidates walk,
  and disagreement withdraws; no candidate adoption is claimed).
- A function CALL whose body contains a directory transition withdraws later
  writes (#3567 feedback P-F5: bash runs the body in the current shell at
  CALL time, so the call-time landing is unknowable from the definition). A
  function definition no longer zeroes an inherited withdrawal either
  (PRR-002): body writes inherit the definition-context withdrawal.
- Same-directory `cd`/`pushd` now refresh `prevCwd` exactly like bash
  refreshes `OLDPWD` (#3567 feedback PRR-006: `cd ..; cd .; cd -` lands at
  the workspace parent, where bash lands it). A `CDPATH=` reassignment on
  the line still does not withdraw CDPATH-eligible `cd` operands.
- The `env -C`/`sudo -D` rewrite consults the existing env-flag grammar,
  extended to GNU abbreviation spellings (`--ch=DIR`, `--c DIR`) so the
  chdir is captured (#3567 feedback P-R1). `env -S 'payload'` was NOT
  modeled here as a re-parsed command — that landed in the G3 round (the
  payload now routes through the destructive and write arms; the G3
  fragment is the operative description, amended in its feedback round).
  Deeper launcher option tables (sudo `-u`, glued `-D..` arity, `time -o`,
  nice) arrive with G3 (#3491 AC3/AC4 residuals).
- Process-substitution masking and brace-expansion write destinations were
  the PR-2 workstream's deferred set and HAVE SINCE LANDED (the G2/G3
  masked-procsub detector family and the W8 brace engine — the G2/G3
  fragments are the operative descriptions). What remains true at this
  fragment: an unquoted `$(...)` operand to a chdir wrapper FAILS the
  rewrite closed (#3567 feedback P-F3) instead of serializing a mangled
  operand, and those commands deny via the parse-failure channel.
- A shell-family launcher whose flag cluster the walk cannot model
  (`bash -oc pipefail 'payload'` — ground truth: the payload executes)
  denies outright (#3567 feedback PRR-003) instead of leaving the payload
  uninspectable. A shell `-c` payload's statements are SPLICED AS A
  PARENTHESIZED SUBSHELL (#3567 final-critic round): the payload's inner
  `cd` can no longer move the parent walk state (`bash -c 'cd src'; echo x
  > f` judges f at the session cwd, bash-true), and payload-internal
  writes judge at the child cwd exactly like bash. On the DESTRUCTIVE arm
  the payload's statements additionally relocate to the uncertain
  sentinel (an inner `cd` re-bases later statements above the session
  cwd) — the fail-closed price is the over-block of no-cd
  multi-statement payloads on that arm. A same-directory `pushd` does not
  grow the directory stack in the model (bash pushes a duplicate entry),
  so a `popd` after a same-dir `pushd` can withdraw where bash returns to
  the same directory — deny-direction, disclosed.
- Denial MESSAGE classes: shapes the #3567 feedback fixes route through the
  fail-closed withdrawal or wrapper-walk channels now deny with the
  withdrawal (`dynamic path target …`) or parse-failure message instead of
  the older single-landing scope message; the verdict (reject) is unchanged
  and the affected pins were re-pinned with the wider class alternations.

# Shell Write Gate: Procsub Masking + Residual Resolution, Brace-Expanded Destinations (G2)

## What changed

- **Process-substitution masking + residual resolution (#3539 W5 / AC1–AC2,
  RC-5)** (`src/hooks/shell-write-detect.ts`, `tool-before.ts`,
  `guardrail-explain-service.ts`): on a parse-failing `>(…)` line the
  detector no longer runs the procsub-only partial scan whose success
  cleared the fail-closed flag — the shape that let one clean in-scope
  procsub write launder a second, undetected outer write
  (`tee >(cat > src/ok) ; echo x > /etc/passwd` admitted). It now masks
  every BALANCED, quote-aware, unquoted-unescaped `>(…)`/`<(…)` span
  (nesting counted; comments and quoted/escaped `>(` never masked; only
  GLUED `>(`/`<(` — spaced `> (x)`, `>>(x)`, `<<(`, `>&(` are real bash
  syntax errors and stay failing), replaces each span with a
  token-preserving `/dev/null` placeholder, and parses the RESIDUAL with
  bash-parser. When the residual parses clean the OUTER writes come from
  the normal AST detectors on it, the masked INNER writes come from the
  FULL detector family run on each span body (#3568 feedback PRR-001 — the
  original per-stage scan recognized only the builtin set plus simple
  redirects, letting tee/dd/curl/sed -i/python/rsync/archive and nested
  `<(` bodies through), and the analysis returns the residual as
  `residualCommand` — the
  gate and `/swarm guardrail explain` resolve surviving writes against
  the RESIDUAL, so `cd ..; tee >(cat > src/ok); echo x > src/f` resolves
  the outer write at the tracked post-cd directory and denies. The
  placeholder is suppressed by the EXISTING sink-device exemption inside
  both the detection and resolver walks (no new string matching: a real
  `/dev/null` operand was already a non-target, and occurrence numbering
  never depends on placeholder removal). Inner writes withdraw
  (`unresolvedContext`, the proven #3518 P-3 channel) whenever their body
  OR the residual prefix before the span carries a directory-selection
  word (`cd|pushd|popd` — `tee >(cd ..; cat > src/f)` denies; a `cd` after
  the span does not withdraw; the backslash-escaped verb spelling
  `\cd ..` withdraws too — #3568 F-04). Anything short of full success — zero
  maskable spans, an unbalanced/ambiguous span, an unparseable residual —
  keeps the parseError UNCONDITIONALLY: the legacy whole-command regex
  fallback still emits its writes for observability, but its partial
  success never clears the fail-closed flag again. `<>` (LESSGREAT)
  remains a write. Read-only `<(cmd)` lines with no writes no longer
  parse-block. `bash -c` payload procsub stays on the W4 unwrap surface.

- **Brace-expanded write destinations (#3491 W8 / AC7, RC-9)**
  (`src/hooks/shell-write-detect.ts`): unquoted `{a,b}` comma lists and
  plain numeric ranges (`{1..3}`, ascending and descending) in a write
  destination — redirect operands, builtin operands (cp/mv/install/ln/
  truncate/rmdir), `tee` positionals, `dd of=` — expand to one write
  target per branch, Cartesian across at most 2 regions and 8 branches,
  emitted identically by the detection walk and BOTH resolver walks so
  every branch pairs with its tracked context (`cd src; echo x > {a,b}`
  admits at ws/src; `cd src; echo x > {a,../../x}` denies). The engine is
  quote-aware on the raw word source, matching executed bash ground
  truth: quoted/escaped braces and commas never expand
  (`'{a,b}'`, `"\{a,b\}"`, `{a\,b}` stay literal), a comma list beats a
  `..` alternative (`{1..3,x}` → `1..3`,`x`), `${a,b}` is a parameter
  expansion (kept literal, denied as a dynamic `$` path), `{a}`/`{a..}`/
  `{..3}`/`{ab..cd}` are literals, and a quoted alternative inside an
  unquoted region still expands (`{a,"b"}`). Real expansions the model
  refuses to enumerate exactly — nested braces, empty alternatives
  (`{a,,b}`), alpha/signed/zero-padded/stepped sequences (`{a..c}`,
  `{-1..2}`, `{01..3}`, `{1..7..2}`), >2 regions, >8 branches — classify
  the write DYNAMIC: a null-path write the gate's existing dynamic-target
  block denies (fail-closed). The procsub-body fallback channel shares
  the engine, so `tee >(cat > src/{a,../../x})` enumerates its branches
  too. Final-critic round: the dynamic refusal is wired UNCONDITIONALLY at
  every destination site (the tee/dd closures' empty-path test previously
  discarded the refusal write — a fail-open that admitted
  `tee src/{a,b}/{c,d}/{e,../../../x}` while bash writes the escaping
  branch), a word with ANY dynamic branch (`src/{a,$(echo b)}`) refuses
  as a whole, and the dynamic-target denial renders the user's SOURCE
  word (`dynamicSourceWord`) instead of brace-substituted branch text.

## Known edges

- A brace expansion in a destination served by detectors outside this
  workstream's site list (curl `-o`, sed `-i` operands) was a FAIL-OPEN
  residue while this PR shipped: the operand read literally, while real
  bash expands it and writes the escaping branch when the target directory
  exists. PR-3 (the g3 closure round) LANDED those site grammars — the
  sed/perl/awk `-i` in-place operands and curl's `-o`/`--output`
  destinations now route through this same brace engine, so the residue is
  closed there.
- Per-site multi-branch semantics are ground-truthed and deliberately
  OVER-APPROXIMATED where bash refuses (final-critic F-2, executed GT):
  a multi-branch REDIRECT operand is an "ambiguous redirect" (rc=1, no
  write; a single-branch `f{1..1}` writes), a ≥2-branch cp/mv destination
  fails "target is not a directory" (no write), and `dd of=` keeps only
  the LAST expanded operand — which can itself be the escaping branch
  (`dd of=src/{a,../ddesc}` writes the outside file). The model judges
  EVERY branch at these sites instead of modeling the refusals: deny when
  any branch escapes, admit when all are in scope — a superset of what
  bash writes, never fail-open. tee/truncate/rmdir are bash-exact
  multi-write commands.
- `> >(cat > f)`-style redirect-into-procsub relies on the placeholder's
  sink-device exemption; a procsub operand in a `cp`/`truncate`
  destination position emits a bogus `/dev/null` write (fail-closed deny)
  rather than modeling the pipe.
- Operator boundaries follow bash's greedy redirect lexing (executed
  ground truth): `<<(x)`, `>>(x)`, `<<<(x)`, `<>(x)`, `>&(x)`, `<&(x)`,
  `>|(x)` and `&>(x)`/`&>>(x)` are operator + `(` — genuine bash syntax
  errors (rc=2, nothing runs) that keep the parse-error block (never
  masked), while `>>>(x)` is `>>` + a glued `>(x)` whose body bash RUNS
  (masked and analyzed, like `><(x)` = `>` + `<(x)` and the escaped-`&`
  midword `\&>(x)`). A spaced `> (x)` never masks.
- An unbalanced procsub span or a masked residual that still fails to
  parse hard-blocks the line even when the legacy fallback found writes —
  deliberate fail-closed supersedure of the old partial-clear behavior
  (one detector-level pin re-pinned accordingly in
  `shell-write-detect-null-device-exact.test.ts`: a `>(cat > /dev/null)`
  body is now analyzed and exempted instead of parse-blocked).
- A `#` comment inside a procsub body can close the span early for the
  scanner; the residual then fails to parse and the line keeps the
  fail-closed parseError (over-block direction only).
- `cat <(ls)`-style no-write procsub lines now admit at the write gate;
  whether the command then runs depends on the host sandbox arm (weak
  PowerShell wrapper without the native Windows runner rejects some
  shapes — an environment behavior outside this gate, pinned
  detector-level in the shipped suite).
- Procsub span BODIES are pushed to the destructive arm with an UNCERTAIN
  child-cwd context (#3568 F-01: a body `rm -rf …` sits at the body's own
  verb position), so any destructive verb inside a procsub body relocates
  to the escaping sentinel — an over-block for benign destructive-in-procsub
  shapes, disclosed (fail-closed).
- `touch` is now a modeled write builtin (every operand; #3568 F-01 — the
  operand loop was previously invisible to both walks, admitting
  `touch ../../esc` at base too), and `cp -t DEST` emits DEST as a write
  target alongside the last-operand destination (#3568 PRR-009 — bash
  writes DEST/<basename>).
- A FULLY-quoted brace token (`dd "of=../../src/{a,b}"`) no longer
  mis-slices across its quote wrapper (#3568 F-02): the braces stay
  literal (bash truth) and the whole literal path is the judged write.
- Numeric brace ranges refuse BEFORE materialization (#3568 PRR-006 —
  the sequence was built first and only then cap-checked: `{1..100000000}`
  cost GB-scale RSS and a 20-digit endpoint never terminated; both now
  classify dynamic in milliseconds). The procsub body recursion is DEPTH-
  BOUNDED (8 levels; reviewer F-b — nested re-masking was super-linear:
  28KB at 4000 levels measured 17.4s vs 6ms base) and fails closed past
  the bound (a depth-cap body surfaces as a null-path unresolved write —
  delta-critic round: the cap originally dropped the nested write
  entirely, reopening the F-01 class at depth 9).
- `/swarm guardrail explain` does NOT mirror the destructive-arm sentinel
  relocation for procsub span bodies (reviewer F-c): the live gate denies
  `true <(rm -rf .swarm)` via the body's uncertain-context relocation,
  while explain can answer allow for the same shape (the write-scope
  mirror blocks the body's WRITE verbs; the destructive relocation is
  gate-only). `scope_validate` DOES deny the shape (DESTRUCTIVE_COMMAND).
  Disclosed asymmetry — the gate is the enforcement surface.
- touch option VALUES (`-d/-t/-r` short-with-separate-arg and the long
  `--date/--reference/--time` forms) are consumed, not judged as targets;
  path-qualified leaves (`command /usr/bin/touch x`) locate the verb by
  basename. `cp -tDEST` (attached short value) is modeled alongside the
  spaced and `=` forms. An UNQUOTED `dd of=$VAR` emits the dynamic
  refusal; a QUOTED `of=$VAR` expansion remains invisible (pre-existing
  at base — the quote wrapper defeats both the word gate and the
  expansion detection; disclosed).

# Shell write gate G3: launcher grammars, interpreter eval clusters, Windows/destructive spellings

## What

Final PR of the #3491/#3539 shell-write-evasion program (three dependency-grouped
PRs; this one closes both issues). Three workstreams on top of the G1/G2 branches:

**Launcher option grammar + fail-closed depth caps (#3491 W3 / RC-2b).** The
destructive arm's wrapper strip handled only BARE `sudo|time|nohup` and
`nice -n N`, so an option-bearing launcher left the option word in verb position
and the identical wrapped command ADMITTED (`sudo -u root rmdir ../x`,
`time -p rmdir ../x`, `nice -10 rmdir ../x` all ran uninspected). A per-manual
option table now walks each launcher's own grammar from a single source shared by
the destructive strip, the write-arm leaf walk, and the resolver walk:

- `sudo` per sudo(8): transparent argless execution options (-E -n -b -B -A -H
  -P -S -k) and arg-taking members (-u/-g/-p/-r/-t/-C/-T/-U plus -D/--chdir
  composing through the W2 quoted-subshell child-cwd transform and -R/--chroot);
  `-l` (with or without a command — it only lists) and the other query modes are
  benign; `-e/--edit` operands are EDIT TARGETS emitted as write-class
  `launcher_write` targets; `-i/-s` with no command opens an interactive root
  shell and DENIES; a command-less sudo with NO query/reset mode is the
  implied interactive root shell (parse_args.c ground truth) and denies
  like `-i`, while `sudo -k`/-v/-l stay benign (documented no-command
  no-ops); `-h` and any unknown option cluster ⇒ "every remaining word
  is a potential execution tail" ⇒ deny-on-uncertainty at the gate (benign when
  no tail remains — a shape that leaves no words to inspect, e.g. after the
  query/reset exclusions above).
- `time` by SPELLING: the bare word is the bash KEYWORD (only `-p`; ground
  truth bash 5.3.9 — an unrecognized dash word IS the timed command, so
  `time -v cmd` runs nothing); an absolute-path spelling selects the GNU binary
  grammar (-p/-v/-q/-h/-V/-i/-a, -f FORMAT, `--`), where `-o FILE` emits the
  timing-report destination as an ADDITIONAL write target (spaced, glued,
  `--output=`, and abbreviation forms).
- `nice` per GNU coreutils: `-n N`, attached `-N`, `--adjustment[=]N`, `--`;
  `nohup` is option-less (bare and `--` transparent); unknown options ⇒
  deny-on-uncertainty.
- Depth caps: the destructive string unwrap chain (fixed 5) and the write arm's
  hop cap (fixed 8) are now cursor-bounded loops with a paranoid absolute bound
  of 64, whose exceedance FAILS CLOSED through an additive channel —
  `dcUnwrapWrappersBounded().depthExceeded` and `WriteAnalysis.unwrapDepthExceeded`
  — consulted by the gate and the `/swarm guardrail explain` mirror BEFORE every
  no-write early return. `sudo`×6 and `command`×14 nesting now reach their verbs
  and deny.

**Interpreter eval clusters + deno (#3491 W7 / RC-3).** The eval matcher tested
whole tokens only, so getopt CLUSTERS never decomposed (`python -Bc`,
`perl -pe`, `ruby -ne`) and `deno` was absent from the interpreter table — those
spellings ran inline code without the `interpreter_eval` classification. Python,
perl, and ruby now have per-interpreter cluster grammars (python: `c` eval with

## What

Five shell write-gate detector fixes, collated from #3569 + #3570 (the
#3491/#3539 program's final-critic residuals) and stacked on the g3 branch:

1. **Nested `sh -c` chains no longer admit destructive payloads (#3570).**

   contains NO SPACE (the truncation signature — a tab/newline-separated

   admitting (levels 1-2 always unchanged).
