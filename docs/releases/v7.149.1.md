# Base-only explorer checkpoint and pending-lane liveness advisory

## What changed

Two long-running lane-lifecycle observability gaps from the tier-L PR-review retrospective are closed (issue #2280).

- **The base-only findings checkpoint is real now.** `write_pr_review_artifact` with `boundary: "post_explorer"` is admissible immediately after the base wave settles — BEFORE the micro wave and trigger evaluation — provided it covers exactly the base-derived candidate inventory (micro ids are refused as `extra:` at that point). This is the one exception to trigger-eval-before-findings; `post_reviewer`/`post_critic` (and any post-trigger-eval `post_explorer` write) still require the persisted trigger-eval artifact and the FULL base+micro inventory, unchanged. The bundled `swarm-pr-review` skill and its findings-persistence contract now document the enforced order with this early checkpoint as the durable compaction recovery point after base settlement (superseding the #2277 interim wording that candidly documented the gap). A reconstructed state carrying council batches without a trigger-eval receipt can no longer widen that base-only inventory — council sources are now gated on the receipt exactly like micro sources.
- **`collect_lane_results` now surfaces a liveness advisory for long-pending lanes.** Lanes pending longer than 3 minutes (originally scoped to `swarm-pr-review:*` modes; widened to every async lane by #2349 before this text shipped) get a `pending_liveness` entry — `{laneId, pendingMs, hostStatus, stalledSuspect, degradedReason?}` — built from a bounded, fail-open host session-status probe (the #2251 pattern, now shared through one probe core). `hostStatus` distinguishes live (`busy`/`retry`) from affirmatively non-live (`idle`, a reported status outside the live allowlist), `absent` (host enumerated sessions without ours), and `unknown` (probe degraded, reason named). `stalledSuspect` is past-threshold AND not affirmatively live. The advisory is ALERT-ONLY — it never cancels, retries, replaces, or settles anything, and the 30-minute presumed-stale sweep remains the only terminal backstop. Below the threshold there is no probe round-trip at all; past it, at most one session-status call per collection, never blocking settlement. Follow-up hardening from the post-merge-review pass: the probe is additionally clamped to the caller's remaining collection budget (a `timeout_ms: 0` poll degrades the advisory per lane as `probe-timeout` instead of spending host time), and an unexpected advisory-accounting failure now emits per-lane `advisory-unavailable` entries rather than silently vanishing — so an absent `pending_liveness` always means "nothing was past the threshold". The early base-only checkpoint is also documented to bind the run (`run_id` must match the later trigger evaluation), and the persistence contract no longer overclaims a guaranteed full-inventory ledger from trigger-eval onward (the receipt plus lane artifacts remain re-derivable; the full rewrite is optional hardening).

## Why

On tier-L runs — exactly where context-compaction risk peaks — the skill promised a durable findings recovery point right after base settlement, but the controller refused every findings write until `trigger-eval.json` existed and the trigger ledger structurally required the completed micro wave, so the promised window was closed. In the same run family, a dispatched critic lane sat `pending` for 20+ minutes with zero observable signal distinguishing "working long" from "hung"; the only diagnostics were a budget-timeout message and the 30-minute stale sweep at completion, and resolution required manual substitution.

Closes #2280.

### Fixed

- **Async lanes whose backing session dies from a terminal provider error now settle immediately instead of hanging until the 30-minute stale sweep.** A lane dispatched via `dispatch_lanes_async` whose subagent died at its first background inference — provider quota exhausted, billing limit, revoked auth — was indistinguishable from a slow lane: it sat `pending` forever and the only operator signal was a repeated collection-budget diagnostic. The host had actually reported the cause all along; `extractAssistantTranscript` read the assistant message's `info.error` solely as an `=== undefined` existence test for its completion-proof boolean and then discarded the value, and the collect loop dropped the resulting zero-text transcript on an unconditional `continue` that ran *before* any readiness reasoning. `collect_lane_results` now classifies that error through the canonical `classifyProviderFailure` and writes a terminal transition with the provider reason recorded (`provider.quota_billing`, `provider.authentication_configuration`, …), so a resource-dead lane terminalizes in a single collection pass with no manual cancellation.

  The settle is deliberately **evidence-based, not time-based**. `getLaneCollectionReadiness` collapses six distinct conditions into `'unknown'` — including status-budget exhaustion caused purely by lane pressure — so an elapsed-time SLO would terminalize healthy lanes that simply had not spoken yet, a worse defect than the wedge. Settlement requires a recorded `info.error` *plus* an independent turn-over discriminator (a stamped `time.completed` or an affirmative `idle` readiness), which rules out an in-flight retry that the host models as an `ApiError` carried on a still-running message. The SDK discriminator is authoritative for the settled status: `MessageAbortedError` settles `cancelled`, never as a provider failure. A lane that produced real output keeps taking the existing route, and a truncated fetch window never settles as error-with-no-output.

- **The pending-liveness advisory now covers every long-pending async lane, not just the five `swarm-pr-review:*` modes.** A plain `dispatch_lanes_async` lane previously had no liveness signal at all. The advisory remains alert-only — it never cancels, retries, replaces, or settles anything — and the probe stays bounded to at most one host session-status call per collection.

- **Synchronous and asynchronous lane failures now report the same underlying condition.** The sync path returned a raw `formatError(...)` string while the async path carried a classified reason; both now normalize through one shape-agnostic classifier, so the same provider condition yields the same category regardless of dispatch mode.

- **A terminal-settle write that does not land no longer tears down the host session.** The teardown is gated on a confirmed terminal transition — `appendDelegationTransition` returns `null` on an exception path and the unchanged record when its guard rejects — because deleting the session on a failed write would leave the record open with no readable session, an unrecoverable wedge. Settle-write failures surface on `collect_lane_results`' `errors[]` (distinctly from host-call timeouts, which keep their own message).

- **`swarm_apply_patch` now says why the fuzzy fallback failed.** When an exact hunk match fails and the opt-in fuzzy fallback also fails, the `context-mismatch` message carries the fuzzy failure reason (`… (fuzzy fallback: <reason>)`) instead of reporting only that the context did not match. Same defect class as the lane fix: the error value was read solely as an `=== null` existence test and its content discarded.

- **Tool-failure reasons now reach the session reflection surfaces.** `agent-activity` previously collapsed a tool's `output.error` into a boolean that only incremented a failure counter, so nothing recorded *why* a tool failed. A bounded, deduplicated, length-capped sample now rides on the tool aggregate and renders in all three reflection surfaces — the deterministic report, the signals block that `/swarm close` always prints, and the LLM delegate prompt.

# PR-review discovery wave recovery

### Fixed

- Hardened PR-review discovery waves against recoverable output-contract drift: operator prompts can no longer override controller-owned row markers, late headers and bounded evidence-pipe damage are classified and repaired, contract failures receive one budget-independent retry, and an explicitly authorized five-of-six settlement persists an immutable disclosure naming the failed dimension and failure class.
- Partial-base admissions now compensate if findings persistence, boundary revalidation, or durable gate-state updates fail, using compare-and-clear cleanup so no orphaned disclosure can claim an incomplete artifact was settled.
